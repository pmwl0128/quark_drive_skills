# Quark Drive Web - 设计摘要

本文只记录 Web 跨前后端的长期设计边界。字段、命令、部署步骤、性能数字和变更过程分别以协议 schema、代码、`dev/**/README.md`、benchmark receipt 与 Git 历史为准。章节编号保留为稳定引用锚点。

## §1 目标与非目标

Web 共用一份 SPA，提供两种运行时：

- **在线版**：公开浏览和浏览器计算；受限事实问答、简化建队与可选诊断解读由在线服务完成。
- **本地版**：`pcui serve` 调用本机四个 skill，并提供 UEP 会话、artifact 和精确调校。

运行时差异只来自 capabilities、部署配置和 adapter。Web 不改变 skill 的 canonical JSON；在线版不提供自由连续对话或用户历史。本地网页不负责唤醒或遥控 agent。

公开队伍码作为现有队伍导入方式，由 `team.code` capability 和共享 adapter 提供单码接口。文本框只在显式提交时查询，
成功取得完整队伍后才更新内容；失败保留原配置。问答只能读取当前问题明确提供的一个码。联网缓存、身份、预算、
熔断和批量策略统一由 team skill 管理，前端不展示策略数值，也不提供独立公开查询页或批量入口。

已有队伍的计算器、实配对位导入在查询前确认整队替换；资料库保留读取预览与保存覆盖步骤。确认或预览之前不改写队伍。

规划中的 Android 应用是**第三个运行时**，不是另一套前端：WebView 承载同一份 `dist`，原生部分只以新增
capability 注入能力（预留名 `mobile.teamcode`、`mobile.capture`、`mobile.overlay`、`storage.secure`），
组件仍不判断 runtime。对战 HUD 若需原生界面，也只宿主同一份 JS 计算引擎，不重写公式（§7.1 的
`calcEngineDigest` 身份链）。

## §2 总体架构与 Build-once 不变量

```text
                        shared SPA / Web DTO
                      ┌──────────┴──────────┐
               OnlineAdapter          LocalAdapter
                      │                     │
            static projection +       pcui local bridge
            browser calc worker       skill workers + SQLite
                      │                     │
             restricted online API    pcui CLI / optional MCP
```

同一提交只构建一次 Vite `dist`，在线部署与本地 wheel 使用同一产物。`dist` 不包含 `runtime-config.json` 或 projection；运行时先读配置和 capabilities，再选择 adapter 与按需 chunk。

组件只依赖 domain hook/repository 和 `RuntimeAdapter`，不得判断 runtime 或直接访问传输层。缺少 capability 就隐藏或降级入口，adapter 不提供伪成功 stub。projection 与 live API 经同一 mapper 进入同一 DTO；所有外部数据都在边界通过 Zod，解析失败视为版本/部署错误。

计算模型与界面依赖分开：`lib/buildState.ts` 保存配置参数、形态和请求转换，`calc/tune/model.ts` 保存纯计算；React 请求缓存独立放在 `useDamageStore.ts`。计算 worker 不导入 React、组件或样式，Vite 的 worker 构建门禁检查实际打包模块，阻止界面依赖跨入计算线程。

### §2.1 语言规范

- UI 文案按用户选择的 zh/en/ja 显示；切换语言不改存储数据。
- 实体 join key 始终是 dex 英文 canonical；显示层本地化，英文回退。
- LLM 使用界面语言 prose，但实体仍输出英文 canonical，再由 renderer 本地化。
- 实体之外不得出现内部标识符：DTO 字段名、role key、JSON 路径和枚举值都不是界面语言的词。做法是双向兜底——投影只喂模型页面同款公开用语（role 标签按界面语言本地化、不带 key），生成后再确定性改写残留标识符；提示词约束不单独作数。C2／C1／C0 是页面自身印出的等级码，属公开词汇。
- 自由输入可混用三种语言，名称归一只发生在 dex/parse 边界。
- 不能解析英文错误消息来推导领域状态。
- 入口词表只放启动外壳渲染的文案；路由页面的文案在各区域的 `defineMessages` 模块里随懒加载 chunk 下发，跨路由组件共用一张共享表，区域模块包含共享表。动态拼接的键用所在模块的 `optionalKey`，不能用只查入口表的版本。

### §2.2 视觉与动效规范

产品品牌命名遵循根目录 [AGENTS.md](../AGENTS.md#核心约定)。顶栏、页脚与分享卡统一署名 Quark Drive，首页主标题按语言使用夸克充能／Quark Drive／クォークチャージ；在线首页中文标题为「夸克充能 · 宝可梦冠军Skills」，本地首页以品牌名和「本地工作台」组织标题。浏览器标签页标题在线版固定为 Quark Drive Web，本地版固定为 Quark Drive Console，不随语言切换或追加其他文字；由 runtime bootstrap 按配置设置，与页内一级标题分开。本地首页使用独立工作台，复用通用工具组件。标志为 `frontend/assets/brand/logo.png`（站点图标与分享卡水印共用），以驱劲能量的橙黑能量容器与紫蓝核心为参考重新绘制，浏览器与主屏图标使用同源尺寸导出。HTML 中的图标使用 release-scoped URL；常规 `/favicon.ico` 入口跟随 current 并禁止缓存，以便浏览器更新收藏栏图标。

在线与本地运行时共享视觉 token 和组件语言。属性色表达宝可梦属性、倍率和等级等数据语义；配置编辑器与配置悬停卡的头部允许用当前宝可梦的双属性色渐变作为身份背景，并保证明暗主题下文字对比度。配置编号、错误和操作状态使用各自的语义 token，不能混为属性或强弱评分。实心操作按钮（主按钮及悬停后填满的同类按钮）统一读 `--action` token：浅色为品牌蓝，深色为深一档的实心蓝配普通暗投影，不用品牌色光晕。配置来源只公开第一层（真实队配置 / Meta 回填 / 自定义 / 估算），由同一组件映射线上来源值并统一着色与说明，页面不各自解释；样本量、置信度和具体来源属于更深层，逐项评估必要性后才进入公开 DTO。动效只提示层级与状态，避免布局动画和持续动画；`prefers-reduced-motion` 必须关闭非必要动画。焦点、选中和错误不能只靠颜色或动画表达。

顶栏主题入口按日间、夜间、自动排列，外框与环境和语言控件等高。自动是未设置偏好时的默认值，实时跟随
系统配色；已有明确日／夜偏好保留。系统变更只更新 CSS 主题，不触发计算重算。全站页底随语言切换，保留
品牌行（标志与 Quark Drive Web）、完整权属与非官方声明和作者／社群联系方式，不重复介绍页面功能；QQ 二维码使用裁去分享卡装饰、保留编码
主体与必要留白的本站静态资源，链接和复制群号是独立备选入口。顶栏和页脚的界面名称按运行时显示 Quark Drive Web 或 Quark Drive Console。

### §2.3 用户资料层

资料 repository 共用记录结构和业务规则，由 adapter 选择存储。在线版使用浏览器 IndexedDB，公开服务不保存用户资料和历史。本地版经已认证的 bridge 保存到用户工作区文件夹，不向在线服务上传。

本地工作区默认是启动命令工作目录下的 `storage`；预构建包会随更新整体替换，其启动脚本经 `PCUI_DEFAULT_WORKSPACE` 把默认位置放到解压目录之外的 `~/.pokemon-champions/workspace`。`pcui serve --workspace <目录>` 可指定位置，前端存储页可直接打开目录，或把当前资料复制到空目录后切换；算子仍在运行时拒绝切换，完成后可重试。所选绝对路径保存在统一的 `~/.pokemon-champions/pc.env` 的 `PCUI_WORKSPACE_DIR`；记住的目录不存在时 bridge 拒绝启动（CLI 直写同样拒绝），不静默新建空资料库，只有显式 `--workspace` 才在该处重新创建。`library.json` 保存队伍、宝可梦和布局，`records.json` 保存历史结果，`sessions.db` 保存 AI 会话与工件。原目录与旧浏览器资料均保留；首次启动将旧的用户级会话库复制到工作区，浏览器资料由用户在前端迁移到空资料库。

存储位置在同一行显示和修改：路径右侧的文件夹按钮调用本机系统目录选择器，初始位置固定为启动时打开的项目根目录，不随存储目录切换。空目标目录自动复制当前资料并切换；已有资料时需显式选择打开，避免覆盖。原生选择器在独立进程运行，不阻塞 bridge 事件循环或跨线程共享会话连接。

JSON 以临时文件加原子替换落盘，资料库写入以 revision 做比较交换；同一工作区仅允许一个 bridge 持有文件锁，多个窗口通过该 bridge 共享资料。目录身份随写入提交，旧窗口不能向切换后的目录误写。保存失败在界面显示，历史结果支持重试，不静默退回临时内存。

| 存储 | 存什么 |
|---|---|
| `sessionStorage` | 页面间交接、表单草稿、计算器工作区：当次会话的草稿，关掉即清 |
| `localStorage` | 语言、主题等少量偏好 |
| IndexedDB（在线）/ 工作区文件（本地） | 用户资料：队伍位、宝可梦箱和布局；另存运行记录的输入和结果 |

- **仿游戏的存放方式。** 宝可梦放在箱子里（每箱 6 × 5 = 30 格），队伍放在按赛制分开的队伍位里。队伍
  不自带配置，只按顺序引用箱子里的个体（至多 6 只）：改一只宝可梦的配置，所有用到它的队伍一起变；删掉
  它，它就从这些队伍里移除，删空的队伍保留名称与备注，直到用户删除。保存队伍时，箱子里已有相同配置的
  个体直接复用，其余放进空格；空格不够就不保存。替换队伍位只替换队伍，被替换队伍的宝可梦留在箱子里。
  箱子本身没有赛制：箱子 1、2 默认名为“单打”“双打”，单打、双打队伍的新成员优先放进对应的箱子；箱子可以
  重命名，名称清空即回到默认名。
  队伍也可以直接从箱子组：在队伍位里增删、拖动或使用前移/后移按钮调整成员顺序，或从箱子里的宝可梦“加入队伍”（空的队伍位就
  以它新建一支队伍）。存储页的成员卡以“×”移出成员，并问“是否同时删除箱子里保存的此宝可梦”：是＝连同
  箱子里的个体一起删（所有用到它的队伍同步移除），否＝只移出这支队伍，取消＝不动。
- **单只存入。** 凡是持续显示一只宝可梦配置的卡片（环境详情的配置条、计算器编辑器、诊断与建队结果的
  成员卡……）都带一个小“+”：把这一只存进当前箱子，满了顺延到其后的第一个空格。弹层与浮动面板里的配置卡
  （环境配置选择器、检索浮层）不带——那里点卡片就是“选用”，再叠一个动作既易误触也不直观。存储页的成员
  本来就在箱子里，所以那里是“×”而不是“+”。
- **编辑个体。** 箱子里的宝可梦可以改配置：存储页的箱子里是完整编辑（换物种/形态、按赛制套用环境配置、
  特性/性格/道具/招式/SP）；全站面板复用同一个完整配置编辑器，并可跳到存储页管理备注和编排。改动作用于个体，
  所以所有引用它的队伍一起变。
- **记录 = 信封 + 正文。** 信封含 `id`、`kind`、`schemaVersion`、创建/更新时间、名称/备注/标签、来源
  （手建、导入、建队、诊断、会话……）与保存时的快照（season / rule / `asOf` / `deploymentId`）。箱子
  条目的正文是 protocol 的 `TeamMemberDoc` 加昵称与所在格：一只具体的宝可梦，而不只是物种；队伍的正文
  是赛制、队伍位与成员引用。交给 skill 的 `TeamDoc`（即 team-json）在读取时由箱子拼出。名称一律 dex
  英文 canonical，显示时再本地化。资料库的 Mega 配置统一写作 Mega 形态 + 对应进化石 + Mega 特性；`teamDoc.ts` 在带 dex 词表的入口完成别名和形态归一。未知 SP、部分已知 SP 与明确零值保留区别，协议支持的 `tera` 与 `completeness` 字段保留。
- **容量是固定配额。** 每个库初始 2 个箱子、单打与双打各 5 个队伍位（5 队 × 6 只正好一箱）。读者可以
  自行加开箱子（逐个）和队伍位（每次 5 个）：访客至多 4 个箱子、每个赛制 10 个队伍位；已授权的浏览器
  （owner / tester key、本地不计量演练、本地运行时）至多 8 个箱子、每个赛制 20 个队伍位。授权由
  `/api/quota` 的 `access` 告知（§7.4）。已开启的永不收回，授权变化只影响能否再开。这是推广层面的约束
  而不是安全边界——资料由用户自行保存。
- **结构与合法性分开。** 库校验结构并按 dex 归一名称；打开时不自动调用合法性检查。在线版可显式跳转确定性诊断，本地版交给 AI 按 team skill 工作流处理，不提供辅助标签或确定性诊断 HTTP 入口。规则切换后旧
  队伍标“规则已变更”，不删除、不改写。
- **用户事实与派生结果分开。** 队伍、箱子、备注长期保留；诊断、对位、伤害这类派生结果只存输入，
  结果按快照缓存，快照不符即提示重算，旧结果不冒充当前事实。
- **运行记录。** 每次消耗额度的请求（问答、建队、诊断、实际配置对位）通过 `lib/runRecords.ts` 在在线浏览器数据库或本地 `records.json` 中
  留一条记录：输入、结果原样载荷和当时的数据身份（season、rule、`asOf`、`deploymentId` 与各赛制的
  `sourceFingerprints`）。它们是派生结果，不进资料库、不随“导出全部”带走，按类保留最近若干条（问答 80、
  建队与诊断各 30、实际对位 12），超出淘汰最旧的已完成记录。失效分几种情况，都只提示、不自动重算：结果所读
  赛制的数据指纹变化即标“数据已更新”并给重跑入口（问答按工具记录里实际读过的赛制判断，只查图鉴的回答不受
  数据更新影响）；season 或 rule 不同时注明当时的规则；当前版本读不懂的结果只保留输入；运行中的问答、诊断、
  实际对位靠心跳判断，所在页面关闭或刷新后记为“已中断”；建队任务在服务端，刷新后凭 job id 继续跟踪，服务端
  已不认的 id 记为过期。被拒绝或失败的问答、诊断、实际对位不留记录。记录按类别在页面首次需要时读取，多个标签页
  之间只同步变化的记录；心跳同步只传记录 id 与时间，不重读结果正文。实际配置对位的 sessionStorage 只保存输入草稿，
  完整结果由运行记录恢复，旧版会话结果迁入历史时不推测数据身份。在线 IndexedDB 不可用时记录只在本页存续；本地文件写入失败会提示重试。代码修复不会把旧结果标为过期：判断依据是数据身份，
  不是代码版本。
- **迁移**：`schemaVersion` 单调递增，升级在打开数据库时一次完成；读不懂的记录（以及与别的记录抢同一格
  的记录）保留原文并标出，随“导出全部”带走，不丢弃。
- **导入导出**：带版本号的 JSON 文件（含布局、箱子条目、队伍引用，队伍另附拼好的 team-json）与 Showdown
  文本。导入经 dex 归一名称；文件里的格位和队伍位空着就沿用，否则放进第一个空位，没有空位的计数略过。
  预检逐条执行与写入同等级的结构校验，坏条目计数跳过，不阻塞其余条目；成员缺失或空间不足时整支队伍不保存，不写残队。空队伍作为记录保留名称与备注。非空队伍同赛制、成员配置相同（与顺序和具体个体无关）即视为同一支队伍，已存在的由用户决定跳过或另存。
- **持久化**：在线版首次写入时请求 `navigator.storage.persist()`，资料页显示持久存储权限及用量；本地版显示实际工作区位置与文件名。
- **共享读取**：资料页、全站面板与其他消费者共用一次观察读取；最后一个消费者离开时停止观察，重新打开时读取新快照。

🚩 在线资料及待迁移的旧浏览器资料按来源（协议 + 主机 + 端口）隔离，跨来源需导出/导入。本地工作区文件不随浏览器或端口改变；语言、主题等显示偏好与临时草稿仍由浏览器保存。

### §2.3.1 渲染与后台工作

图鉴与环境排名的长列表渐进挂载，搜索与筛选始终遍历完整数据；滚动接近尾部或点击显示更多时继续展示。问答历史的正文索引与实体词表只在打开历史或读取回答时准备。

交互浮层在悬停、聚焦或父菜单打开时预取模块，未预取时显示自身的加载占位；模块就绪后直接挂载，避免额外的 Suspense 揭示等待。预取不挂载组件，不启动资料库观察或读取。

计算工具切换时保留输入与视图状态，隐藏工具释放 Effect 和订阅，停止派发后续批次。浏览器引擎将即时计算与反推、速度约束和耐久预计算分开排队；后台池按设备核数限制宽度，已经派发的批次可以完成，旧任务的结果按输入身份隔离。AI 请求和服务端任务在页面切换后继续写入运行记录，不使用隐藏计算工具的暂停方式。

首页循环动效仅在所在面板选中、进入视口且文档处于前台时运行；减少动态效果偏好关闭循环。指针动效的测量与样式写入合并到每帧一次。

### §2.4 全站资料库工作区

队伍与箱子是应用级对象，不属于任何路由：外壳持有一个“队伍与箱子”面板，任何页面都能打开，切换页面不关闭。

- **入口与形态。** 顶栏最右侧的精灵球按钮开合面板（面板从右侧出来，入口就在右端）；按钮在任何页面都
  一样，不显示资料内容。面板非模态、不加遮罩，页面照常可操作：宽屏停靠在右侧页边并优先使用页面留白，放不下时浮在页面右侧，手机上是底部面板；短横屏的内容和操作区一起滚动，保留可用的选择区域。检索栏独立锚定在顶栏入口下方。面板里的队伍成员与箱格在鼠标悬停或键盘聚焦时显示配置卡，触屏点击直接选择，
  可就地编辑或删除（编辑窗与存储页是同一个配置编辑器，带环境配置）；文件、备注、队伍编排等完整管理在
  存储页。Esc 由外壳的层栈处理，一次只关闭最上层。对话框打开时移入焦点，Tab 保留在对话框内，关闭后还原焦点；删除确认默认聚焦取消。
- **当前队伍。** 读者可以把一支队伍设为当前队伍，面板默认展示它。只记 id 与赛制（`localStorage`），
  所以不开面板也能读到；队伍被删即清除。
- **页面约定。** 页面不直接读写资料库，只登记自己**能接收什么**（接收端：一支队伍、一只宝可梦、整个箱子
  的物种列表）和**能交出什么**（来源：当前页上的队伍或配置）。面板把与当前选择匹配的接收端列成“填入当前
  页面”，把来源列成“从当前页面保存”；页面上的放置区把拖进来的内容交给同一批接收端。面板不认识任何页面，
  页面不认识存储；页面只在自己可见时登记（隐藏的标签页不登记）。新页面接入只需登记接收端和来源，来源显式声明 `origin`。工作区按消费字段订阅状态；打开面板、拖动与注册来源不触发只读操作函数的页面重渲染。
- 页面自己的“保存队伍”控件（如计算器我方/对方菜单）不另写保存逻辑：它请求面板打开到对应来源的保存
  对话框，与面板里“从当前页面保存”是同一条路。
- 反方向也能拖：页面上的队伍卡成员、计算器各编辑器的头像（不含队伍条与速度表）、全对位结果表的表头头像和耐久目标的双方头像可以直接拖进面板的箱格
  （放进那一格，或其后的第一个空格）；面板里的宝可梦拖到另一格就是挪位。
- 交给页面的是真实配置：计算器把它当作钉住的成员，空着的字段不被环境自动填充覆盖。
- 入口包里只有这套约定与顶栏按钮；Dexie 与面板随第一次打开面板（或进入存储页）才加载。

入口未被发现时只显示小圆点，加载后以两次轻微扩散和一次性可关闭气泡介绍用途。气泡不抢焦点，完整导入、
编排仍指向存储页；点击入口后永久恢复普通精灵球。提示状态只是浏览器本地偏好，不记录或上传资料库内容。

### §2.5 首页

`/` 按运行时选择首页，保持同一份 SPA 构建；两端的旧排名查询链接都重定向到 `/ranking`。在线首页使用 `HomePage` 与 `pages/home/`，按 capability 显示诊断、简化组队和问答。以下开屏、示例和插画约定适用于在线首页。

本地 `LocalHomePage` 是独立工作台：当前资料库队伍、待决策优先的最近会话、新任务和确定性工具为主，近期队伍与环境入口为辅。复用资料库、名称/图片、控件和工具交接，不请求在线模型服务；请求创建前保留草稿，选择的队伍以配置快照附入会话。页面读取至多四张会话卡与待处理、当前队伍相关会话的完整计数，并由 SSE 触发重读；服务端计数不加载全部会话附带的队伍快照。数据块独立加载，失败不阻挡其他入口。详情与列表共享服务端状态投影。

- 待你决策或复核未通过的会话置顶。上手清单（导入队伍、连接 AI 助手、创建第一个任务）只在仍有未完成项时出现，助手一项以 bridge 报告的 companion 安装状态为准；静态 projection 与正在服务的 skill 数据不一致时单独提示。最近计算列出工作区运行记录中的实际对位结果，工作区路径与备份方式在页底。
- 视觉沿用在线首页的语言但不做展示：开屏为紧凑的浅色 stage（品牌色晕染、细网格、展示字体品牌名与「本地工作台」胶囊标签），区块标题用与在线一致的「小标记 + 标题 + 细线」，没有插画、入场动画或循环动效。会话列表与会话页共用同一套面板、标记和 stage token。

- 首屏只依赖握手：不发数据请求、不放 sprite（任何 `GameImage` 都会先拉图片索引）。环境速览位于首屏以下、接近视口时懒加载，以文本为主、各赛制列前十，失败只影响自身。首页在入口 chunk 中，其文案留在入口词表。
- 任务区的面板叠放在同一格、按最高者定高，切换标签不移动页面；草稿保留在本次浏览器会话。交接只预填目标页、不代为提交：诊断交文本与赛制；组队交赛制、打法、核心与倾向战术（首页只列天气、顺风、戏法空间、强化，完整列表在向导）；问答只预填问题。首页问答示例与问答页共用同一组。
- 诊断按赛制各维护一支作者已公开的完整示例队，原文链接、作者、原赛季与规则记录在 `pages/home/example.ts`，页面不显示出处行；这是人工选定的教学内容，不从 projection 导出真实队库。示例只在其规则与运行时规则相同时预填；未经编辑的示例随赛制切换而切换，用户自己的文本不随之改变。
- 插画是界面示意，不是结果：不出现可被读作事实的伤害、使用率或推断数值，装饰层对辅助技术隐藏；颜色只取站内数据语言（击杀档色、属性色）与品牌蓝。示意本身不能违背规则事实：开屏击杀表的行与列是同一份按名次排列的成员（各配一个属性），每格是行成员本系招式打列成员，倍率按属性相性表，击杀档只在该倍率的合理范围内取，「无效」只出现在相性为 0 的格子；点开的读数用站内术语（输出／承伤、本系、倍率、确／乱 N），同一成员对自身为同速。
- 首页不放解释性小字，控件标签即说明；赛季、规则和数据日期只在顶栏出现。开屏与安装区在浅色主题是浅色面，靠淡品牌色晕染、细网格、描边与阴影和页面区分，不用大面积实心深色块或多色渐变；深色主题另设一套，比面板高一档并带细边。开屏底部渐隐，任务区压在其上。两套颜色集中在 `styles.home.css` 的 `--stage-*` token。
- 展示标题（开屏、区块、安装区）：开屏主标题分级：产品名「宝可梦冠军Skills」是品牌名上方的小号胶囊标签（以标志核心为圆点），品牌名取展示字号，其下是副标题；语义上仍是同一个 h1，DOM 顺序为「品牌 · 产品」。中日文没有空格可断，标题文案用 `|` 标出可换行的意群、用 `[…]` 标出强调词（副标题其余文字取次要色，强调词取品牌蓝）（`pages/home/Phrases.tsx`），意群内不换行，不按字硬拆；英文照常换行。标题里的拉丁字母用自托管的 QD Display（Saira 子集，见 `frontend/assets/fonts/qd-display`），中日文回落界面字体。首屏以下各区块用同一种区块标题：取自该区内容视觉语言的小标记（对战计算＝KO 色阶，环境速览＝属性色名次条，安装区＝标志核心）、标题和延伸到右缘的细线；对战计算区垫一层与开屏同款、四周渐隐的细网格。
- 动效：入场只播一次，全页只用一种：区块淡入并上移数像素就位，文字同时由轻微模糊变清晰；同组元素按固定短间隔先后到达，不叠加扫光、描线、打字等其他效果。首屏在加载时播放（自上而下：标签、品牌名、副标题、按钮，随后是任务区）；首屏以下的区块在第一次进入视口时各播一次（先标题，再内容），已在视口内的内容从不先隐藏。入场只改透明度、位移和模糊，不移动布局。悬停时各插画演示对应工具；组队流程图只在其标签可见时循环，这是 §2.2「避免持续动画」在首页的唯一例外。`prefers-reduced-motion` 时全部静止，也不隐藏任何内容。

## §3 协议层（`frontend/protocol`）

协议包 Zod-first：schema 是运行时权威，TypeScript 类型由 `z.infer` 派生。React 不直接消费 raw skill JSON、投影内部文件或 provider 响应。

capabilities 只负责发现功能，不负责授权；每个端点仍独立校验身份、命令、参数、体积、超时与并发。版本身份分工：

- `webProtocolVersion`：API 兼容性；
- `uiBuildId`：SPA 构建身份；
- `skillFingerprints`：实际 skill 代码和数据；
- `deploymentId`：完整发布装配；
- `calcEngineDigest`：浏览器计算引擎快照；
- `environment.sourceFingerprints`：按赛制的数据身份（当季 meta 面板与该规则的真实队库），即 opponent cache 自校验所用的同一组哈希。它只随数据变化，不随代码变化，供派生结果、离线缓存与发布内容判断“数据是否已变”。

raw skill 只在 bridge mapper 转换；projection 构建复用同一 mapper。JSON Schema catalog 从 Zod 单源生成并做精确再生成检查。local/online bridge 都提供 `/api/openapi.json`；显式路由目录必须覆盖全部公开 `/api` 路由，所有 `$ref` 可解析，release 不依赖源码路径。

## §4 本地 bridge（`pcui serve`）

### 4.1 进程模型

FastAPI 使用单主进程。dex、meta、calc 和 speedline 走通用 NDJSON worker；worker 失败可回退一次性子进程，结果必须等价。🚩 常驻 meta worker 在整个生命周期内缓存已读的面板文件：部署切换会重启进程所以安全，开发机原地刷新数据后需重启 bridge（问答常见配置缓存在检测到快照变化时会回收空闲 worker，其他路径不会）。team 请求通过 `team.py session` 批处理，使批内 sibling 复用；不得把私有 dispatch 当长期接口。

用户配置统一位于 `~/.pokemon-champions/pc.env`。端口、provider、密钥和主机路径不写入仓库，也不按运行目标拆成多个 env 文件；本地进程只读取自身需要的项。API 只接受白名单操作和受控参数；文件内容由客户端内联。工作区接口接受用户选择的目录，并只操作固定资料文件；其余 daemon 操作不接收任意路径或 argv。

### 4.2 会话与 artifact

SQLite 是会话事实源。artifact 按 `kind + canonical payload` 内容寻址、不可变并可复用；ledger 只追加，session head/revision 在同一事务中 CAS。原始 artifact 文本逐字节保存，用于 receipt、frame 和 slate 重放。新会话的 meta 必须是对象；读取旧版非对象 meta 时按空对象展示，保留数据库原始内容。

目录导入导出只是兼容层。daemon 存活但不可达时，CLI 禁止直写 SQLite，以免 split-brain；只有确认 daemon 未运行时才能离线访问。

### 4.3 本地安全边界

bridge 默认只监听 loopback。浏览器用 URL fragment 中的一次性 bootstrap token 换取 HttpOnly、SameSite=Strict cookie；CLI 使用用户私有 daemon secret。`pcui open` 凭 CLI secret 向 daemon 申请新的一次性 token（数分钟内未用即失效，浏览器 cookie 无权申请），用于第二个窗口、会话直达链接和 bridge 重启后的重新登录；cookie 仍只在单个进程内有效。服务端校验 Host、Origin、体积和时限。目录选择仅用于已认证的工作区切换，其余任意路径、命令与跨域调用均被拒绝。

开放 LAN 必须显式指定 host 并确认风险；这不是多用户安全部署。

## §5 agent 集成

`pcui` CLI 是本地协作的权威入口，提供 session/artifact 操作、白名单算子、环境诊断、登录链接和 companion skill 安装。companion 只说明如何按 UEP 读写工件，必须显式安装，不能由 Web 或 pipx 偷偷注入 agent；命令绑定当前解释器或已安装的 pcui 可执行文件，可在任意工作目录执行，`doctor` 与 Console 按「与当前安装模板逐字一致」判断已安装或需更新。agent 每条命令显式传 session id；`session use` 只供人手动操作，其共享快捷选择按工作区限定，`PCUI_SESSION` 是显式的 shell 覆盖。大体量输出用 `run --out` 保存可供后续 gate 直接读取的完整结果正文，终端保留退出码与工件摘要。`run <op> --session <S>` 在运行开始时绑定 revision，并在同一事务中提交输入与 gate 输出；冲突时拒绝提交，不自动合并。同一会话同时只接受一次算子调用。连续相同 gate 的重复调用不增加 ledger，新的草稿或回答之后再次应用相同工件仍记录新顺序。`session wait <S>` 长轮询面板的 decision / intake-answer，读者作答后 agent 自动继续，超时退出码 3。

手写工件通过 `pcui artifact put --revision <R>` 提交，R 是开始工作时从 `session show` 读到的版本；不允许 CLI 自动选择最新版本号。发生冲突后先审阅新状态及原结果，再决定是否重新生成和提交，不能只换版本号重试旧内容。

`pcui mcp` 是同一 API 的薄适配，不形成第二套会话协议：stdio 上逐行 JSON-RPC，每次调用都转给正在运行的 daemon（重启后按 daemon.json 重新找到），自身不持会话事实。输入接收不等待工具执行，工具调用有界并发；坏参数或文件保存失败只影响该次调用，执行失败不伪装成成功。等待读者采用短轮询，可取消；取消已发出的算子调用会停止交付该次 MCP 响应，daemon 中已开始的计算及工件提交仍可能完成，应重读会话确认。工具与 CLI 一一对应（会话列表/详情/新建、读写工件、运行算子、等待读者作答、签发登录链接）；artifact append 必须提交 revision 并原样返回 CAS 冲突，适配层不得自动合并。实现不依赖 MCP SDK，以免发行包新增运行时依赖。注册由用户自行完成（`pcui mcp --print-config` 打印 Claude Code 与 Codex 的写法及显式工具超时），不由 Web 或 bridge 写入任何 agent 配置；远程传输不引入。

## §6 本地 UEP 会话面板

会话面板是 UEP 工件的只读透镜和 checkpoint 输入面。checkpoint 正文与会话 revision 组成同一决策快照：加载或读取失败时不接受提交，快照改变时清空原选择并重新确认；等待到期时，即使没有新事件，交接提示也重新计算。

| 环节 | 页面职责 |
|---|---|
| audit / frame / slate / answer-audit | 渲染 agent 写入的事实、候选和审计结果 |
| checkpoint | 以当前 revision 写 decision；冲突后重读并重新确认 |
| intake | 把 agent 当前的问题批次渲染为表单，以当前 revision 写 intake-answer |
| matchup / tune | 交给计算页直接运行确定性工具；本地诊断由 agent 在会话中完成 |

面板不重写或强校验 agent artifact；已知形状尽力摘要，不匹配则显示原文。SSE 只通知，事实仍从 SQLite/session API 重读。本地页面位于 capability 门控的动态 chunk，在线端不得请求。

每个标签页只开一条事件流，由外壳保持，任何页面都能察觉断线：未命名消息是 artifact 追加，`session` 是会话新建、改名、归档或删除，`activity` 是算子运行或 agent 等待的开始与结束，`hello` 与每 15 秒的 `ping` 证明连接仍活；超过约 40 秒无消息即视为断开。断开后用有超时的健康探测区分 401（bridge 已重启、此页 cookie 失效，全站提示运行 `pcui open`）与无响应（服务停止），两者都持续重试；连接代际保护使前台切换和旧探测结果不能额外开启事件流。重新连上后发出 `resync`，各读者重读而不信任旧副本。

快速计算是无会话工具；复杂调校和自然语言目标写入会话，由 agent 转成 benchmarks。agent-authored artifact 必须按不可信输入处理，renderer 宽容解析但不能执行内容。

新建会话保留自然语言意图，并可附赛制、任务倾向、队伍配置与环境快照；这些是 intake 输入，不代替 agent 的名称归一和 UEP。首页与会话列表使用同一个新建表单，CLI 的 `session create` 写入同形状 meta，供对话先行时由 agent 建会话并给出直达链接。旧的仅意图会话继续有效。交接说明绑定具体 session id 并随状态变化（开始、面板决策后继续、复核未通过后修改、助手停下后接着做；待决策与复核通过时不显示），网页不启动 agent。会话摘要带最新 ledger 条目的 kind，用来区分「面板刚写入决策」与「agent 刚提交产物」。

agent 尚未越过、读者也未在面板作答的 intake 批次使会话进入「待你回答」，与待决策、复核未通过同列为需要读者处理。daemon 另外报告它亲眼所见、不入 ledger 的实时状态：正在为该会话运行的算子（未产出结果的失败保留十分钟）、正在 `session wait` 的 agent（每次轮询续期，超时即消失），以及已被等待中的 agent 取走的最新面板作答序号。前两者让页面可以说「正在运行」「正在等你」，后者让交接卡改为「助手已收到」而不再要求读者转交；进程重启后这些状态清空，不影响 ledger 推导的状态。

标题与归档是读者自己的记录，存在独立表中，不改 ledger、不改 revision，因此不会打断 agent 或面板的 CAS。删除移除会话、其 ledger 及不再被其他会话引用的工件。新建表单附带资料库队伍时一并记录 `meta.teamRef`，首页当前队伍据此链接到相关会话；会话结果可以写回这支队伍：队伍换上结果配置，原配置先复制到同赛制的空队伍位（「修改前」），没有空位或箱子空间不足时什么都不改。撤销只在当前记录与本次写回版本仍一致时执行，不能覆盖后续编辑或占用其他队伍的槽位；冲突时保留修改前版本。诊断类会话按 ledger 将 `diagnose` 配对到它之前最近的 `team`，不能与之后手动写入的 team 混用；旧会话可回退到 `meta.team`，报告缓存有界且包含实际队伍身份。bridge 合成与在线诊断页同一份报告，合法性在读取时按当前规则校验。状态由当前 artifact、pass 值与 ledger 顺序派生；空会话为待交接，收到产物不证明 agent 正在运行，新草稿、决策、问题或回答会使旧复核失效。摘要只读取当前状态所需的 artifact，不改写其原始字节。

## §7 在线版

### 7.1 静态投影与浏览器计算

projection 是公开裁剪 DTO，不是 skill 数据镜像。它可以包含 dex/meta 展示、趋势、图片 manifest、加工配置和 opponent matchup 参考；不得含 raw real-team JSONL、build-state、quarantine、PII 或可还原整队的数据。公开 sets 剥除 provenance，页面不得暗示其来源或强度。

projection、bridge、skills 与 SPA 共享 `deploymentId`；内容 URL 带发布身份，manifest/capabilities 不一致时拒绝混用。不得直接暴露 `.agents/skills`。

发布期不变事实使用会话级 single-flight 缓存，键包含 deployment、数据种类、format 和实体；成功项做有限 LRU，失败项可重试，旧请求不得覆盖新依赖键的可见状态。

伤害、速度和耐久快速试算使用与 ncp 同源的 vendored JavaScript，并在 Web Worker 中懒加载：

- OnlineAdapter 的 damage/damageBatch/speedBatch 在客户端完成，组件不区分宿主；
- opponent cache 是去来源的标准配置参考，不替代用户队 live matchup；meta-only 目标不伪造攻击档位；
- 模拟大表选中后立即创建结果卡并定位，详情按物种分片按需加载，覆盖该物种所有配置及反向伤害。
  分片与完整矩阵共用映射与证据到期规则，配置取共享 `oppsets`，不在首次点击时解析整张详情矩阵；
- 计算器自动配置与模拟表头共用轻量 `oppsets` 视图，不为单只配置加载伤害矩阵。自动填充取真实队伍
  聚合中占比最高的完整配置；聚合为空才回退到各字段边际众数组成的 Meta 配置。手动选择始终把该
  Meta 回填列在真实配置之后。配置选择卡直接展示完整的道具、特性、性格、招式与 SP；悬浮信息只
  用于确认已经选中的配置。批量计算结果携带本次输入的只读显示快照，结果过期后不得拿当前编辑值
  冒充计算时配置；
- 跨规则交接只影响 team 派生的参考配置和网格。DTO 携带 `teamEvidenceExpiresAt`，并在同一 deployment
  提供 native 视图；浏览器到期后原位切换，原生样本不足则显示无参考矩阵。dex、meta 和计算引擎始终
  使用当前规则，不能随 team 证据延长；
- `team.tune` 是受限确定性 API，浏览器反解不能标作精确 tune；两者必须描述同一帧，浏览器侧的调校请求与 `tune` 算子一样关闭出场降能力（`switch_in_drops:false`），否则同一组输入会给出两个答案。同理，耐久调整页只提供 `tune` 算子能保留的场地条件（赛制、天气、场地、我方墙类），不复用计算器的完整条件面板；
- 计算页各工具共享一份队伍与战场（`roster.tsx`）：双方队伍与配置、出场位、各方所选招式、赛制/天气/场地/双方场地状态。A 方恒为我方、B 方为对方；攻守互换交换整份数据而不是翻转某个工具的视角，三个工具的互换入口统一放在两张卡片之间的缝隙里、不占布局。各工具只读取、也只显示自身计算能保留的条件，其余条件留在共享战场里、不进入该工具的数字（戏法空间是只有速度线读取的全场条件）；工具自有的读数状态（乱数档、会心、耐久目标）不进共享层。每只宝可梦有稳定 `uid`，跨工具的引用（耐久目标、还原点、自动填充）都按 uid 而非下标。没有可恢复工作区时的示例是当前双打排名第一、第二的最常见配置，从排名实时读取而不写进代码，也不随赛制切换重填；
- 速度线以我方当前选中的宝可梦为参照：环境表的着色和调速提示都相对它；对方卡片是用户自选的对照项而不是对位。它只提供改变速度数值或先后手的条件（天气、场地、各侧顺风、戏法空间），后两者各只有一个开关，直接显示在队伍条上。送往速度引擎的输入显式补齐空性格（中性）和未填速度 SP（0），不落到引擎的胆小 / 32 默认；轻装只在特性已触发时计入。速度档预设只改写性格的速度一半与速度 SP，另一半属于伤害与耐久。环境表只读、不写队伍：实配列来自已加载的 oppsets 目录，计入天气与场地、不计任何一侧的顺风；队伍里同物种宝可梦的配置按同样条件并入该物种行的实配列（与某个真实配置完全相同时即选中它，否则作为自定义配置置顶），实配格可切换显示哪一套（卡片与环境配置选择一致，末尾是 Meta 回填），切换只影响本表。某侧开启顺风时，显示该侧队员配置的实配格按顺风后的速度读数并标出 ×2，排序与着色都用这个数，弹窗里的配置卡仍是配置本身的速度；
- 天气和场地的出场特性在共享队伍层分别处理，只读双方当前出场位的实际形态特性：单个来源自动套用，两个来源按实际出招顺序由后行动一方的特性覆盖先行动的一方。出招顺序计入引擎的速度修正（包括讲究围巾、顺风）及戏法空间的反转；同速不模拟随机拼速、不自动套用。没有来源或速度不可用时保留现有条件。来源提示在四个工具里均保留，符合当前实际天气/场地的来源标绿、未生效的标红，不追加自动套用文字；同速保留待手动选择提示，且仍可点击套用，浮动提示及无障碍名称说明生效状态。手动修改天气/场地、切换工具或无变化的输入提交不重新触发自动套用；当前出场来源变化或影响两个来源出招顺序的条件变化才重新判断，天气和场地互不清空。
- SPA 与 projection 的 `calcEngineDigest` 不一致时拒绝计算。
- 计算器的 pokepaste 导入在**浏览器内**解析，不走 §7.5 的服务端队伍文本解析：那条链路是配额后的在线能力，而计算器必须在在线运行时纯客户端可用。它只认 Showdown 导出块，名称原样交给 dex 归一（dex 是唯一命名权威）；本篇努力值按同等投资折算到 66 点 SP 预算并在界面上声明折算，不静默改写用户配置。

公式权威和 vendor 边界见 [`../dev/design.md`](../dev/design.md)；Web 只做宿主适配。

### 7.1.1 环境详情页的两条数据轴与页边栏

meta 详情页承载两条独立数据轴。usage 轴（ranking/details）与 KO 轴（`ko_*`）默认来自同一格式的 bulk 快照；
备用来源或历史保留时数据时间可能不同，
因此 KO 是独立 DTO 与独立投影文件族。页面由两张卡组成：使用率卡只放 usage 轴，击倒卡自带快照号与
`updatedAt`（有招式层时另注 `coverage.moveShareCapturedAt`），不并入使用率卡，也不共用它的数据戳。

两张卡都是可以单独截图的完整单元，这是页面的承重目标：

- 使用率卡在 1920×1080 首屏内完整显示；十行面板一律完整展示、不折叠。行距优先保证久读不累，
  因此不再为更矮的屏幕继续压缩，那里靠分享图拿到完整画面。
- 快照（赛季 · 规则 · 使用率数据日期）页面顶栏已经给出，卡内不重复；分享图没有顶栏，由画框印出。
  日期读 projection manifest 的 `environment.asOf`，不在前端另存。变化基准写在各面板的表头。
- 卡片按自身宽度（container query）而不是视口排版，分享图因此在手机上生成时也是桌面版式。
- 属性色只用这只宝可梦自己的属性：主属性色画占比条、榜首数值与 SP 热力格，双属性画顶边色条。
- 变化列 = 本期对比 usage_trend 窗口首期（相邻两期只差一到三天，读不出变化）。首期为 null 表示当期
  不在前十，显示“新”而不是差值；|Δ| < 0.5 以淡色显示，只有零变化留空；方向用字形与中性色，不用红绿（同下文 KO 方向的理由，
  且占比涨跌不是好坏）。
- 主流配置条只取 `oppsets` 里 `realTeamBacked` 物种的真实变体，modal 在首位；没有真实变体就不渲染，
  不用 Meta 回填——截图会把按字段边际拼出的配置读成有人在用的配置。多套变体只能手动翻页，不自动轮播：
  那是数据页上的持续动画（§2.2），也会让截图随机截到某一套。条上不印 `coverage`：它是“道具+特性”
  簇的覆盖率，不是这一整套配置的占比。
- 分享图纯前端生成，把同一组卡片组件渲染进固定比例的离屏框（16:9 输出 1920×1080，3:4 输出
  1440×1920）再转 PNG；框自带 `data-theme`，所以图片主题可独立于页面选择。图中不含任何控件，
  所有图片 eager 加载并等待解析完成后才截取。截图库与弹窗是按需加载的独立 chunk。
- 使用率分享卡的品牌行左侧为 Quark Drive，右侧为本地化来源与当前赛季 / 规则编号。固定站点
  `champion.mpan.top` 位于常见队友区域的右下方，在线版和本地版一致，不取浏览器主机名。

- KO 对象的公开契约只有顺序、没有占比，DTO 因此**不含** percentage 字段——留 nullable 会被读成实测 0。
- KO 招式占比是保留层：未采集时为 `null` 而非 `[]`，`coverage.moveShare` 同步声明；渲染必须占位说明，
  消失会被读成"没有击倒招式"。
- 本期零记录方向使用历史回填时，`coverage.panelReusedFrom` 携带各面板的原赛季、规则、格式、快照与时间。
  KO 卡片在该方向展示原赛季和时间；另一方向仍显示本期数据。回填面板不冒充本期趋势观测。
- KO 对象身份只到种族级（全国图鉴编号），同一编号在一条列表里重复时两条都保留并标记，不去重。
  打印出来的名字保持种族级，但 `slug`/`key` 必须指向**一个真实形态**——sprite 和链接没法指向一个种族。
  能被 dex 精确命名的种族就是它自己，否则用 dex 给那个光秃秃种族名指定的代表形态；使用率名次跟着同一个
  形态取，于是"画的是谁、算的是谁、点过去是谁"是同一句话。
- 方向不用绿/红：对位网格已占用 KO 分档与 check 等级色带，暖/绿在此会被读成评价。方向用 build 标签的
  蓝/紫加箭头字形，灰度与色觉障碍下同样可读。
- 页面展示深度由 mapper 单点裁剪（`KO_PANEL_LIMIT`）。投影是公开裁剪 DTO 而非 skill 数据镜像，
  shipped 数据保留更深的列表，不代表投影要一起变厚。

详情页里所有宝可梦行（队友、两个 KO 栏）都跳**同一 format 的环境详情页**，不是图鉴卡片：读者正在读环境
事实，下一步想要的是同一种页面。种族级行只能跳到那个代表形态——这是"判不出形态就落到第一匹配项"，不是
假装来源给了形态。

每一行都能悬浮出历史小图，数据来自两份文档：usage 面板与**队友**在 `usage_trend`（details 的时钟），
它同时喂变化列，所以随页面加载、全卡共用一次请求；两个 KO 栏在 `ko_trend`（KO 自己的时钟），
首次打开其浮窗才加载。图分两种，因为事实分两种：有占比的面板画占比，只发布顺序的面板
（队友、KO 对象）画**名次**——1 在顶、单位是"位"、向上是变好。把名次画在占比轴上等于凭空造一个没人测过的
量。只有一期时就画那一个点并写明"仅 1 期"：对一条只采集过一次的轴，一个点就是全部真相，画成"数据不足"
会被读成"没有数据"。

站内检索是一层共享外壳，环境、图鉴与计算同用，每处只自己决定宽度与内容。环境这一处面板内是搜索加榜单，
筛选是挂在它右侧的独立卡片，入口是搜索框右侧的小按钮。承重约束是**筛选项与被它改变的结果必须同屏**：
facet 放页面另一侧要"在右边选、到左边看"，塞进栏内下钻则要"点回去才知道选中了什么"，两种都不成立。
浮层允许压住正文，这正是它的作用；勾选实时改左侧列表，浮层保持展开直到按它自己的关闭按钮。

榜单页与详情页挂的是同一条边栏，区别只在筛选的作用域：详情页用它换当前这只，榜单页**只筛栏内列表，
不动外层卡片网格**——外层网格本身就是榜单，从一份排名里静默抽掉几行会把它读成另一份排名。

关闭是分层的：筛选卡的 × 只关筛选，检索面板的 × 关面板并带走筛选，Esc 关最内层；点击页面上面板以外的地方
也会关闭（对话框、悬浮卡等挂在页面外壳之外的浮层和资料库面板不算）。点击榜单条目只跳转，面板不动——浏览
榜单是连续动作；跳到另一页后，同一种检索仍是打开的（本次访问内记住，刷新后从关闭开始）。面板必须渲染在
页面的每个分支上（含两只之间的 loading 闪帧），否则每次跳转都会卸载它并静默丢掉筛选与搜索词。

检索入口是顶栏最左端、网站图标之前的放大镜图标，每个页面都有、位置不变（`/` 键同样打开）。页面登记自己的检索
（环境榜单、图鉴、计算器的配置挑选），入口就打开它；存储页打开用于存入箱子的配置检索；没有自己检索的页面（辅助、会话）打开环境榜单检索，
面板头部带单打/双打切换，初始跟随当前队伍的赛制，点一行进入该宝可梦的环境详情，详情页上同一检索仍开着。
面板是挂在入口下方的浮动卡片，固定高度，不占页面整高、不推开页面；放不下时向左挪，并避开右侧停靠的资料库
面板。手机上面板横跨屏宽，筛选卡盖在它上面。

筛选依赖每 format 一份的倒排索引投影文件——逐只 detail 是懒加载的，客户端自行聚合会退化成按 roster 逐个
请求。facet 值是英文 canonical（join key），显示层本地化，语言切换不改变键。

环境页有两个数据源：官方数据（游戏内导出的全分段统计）与竞技环境（Top Meta，队库在同一组字段上的计数），竞技环境再分赛季与规则范围。范围按钮直接显示 runtime environment 的 season / rule 编号，跟随 current 权威更新，不硬编码代号。状态在 URL（`src`、`scope`、`cmp`），链接与刷新都保持同一视图。竞技环境文件只在该视图或对比打开时请求，默认路径不多一次请求。榜单页标题后接数据源与该来源的选项（官方数据为趋势图，竞技环境为赛季 / 规则）；对比紧接趋势图或范围按钮，样本与说明位于右侧，紧邻单双打切换左边。窄屏按分组换行。趋势图只属于官方数据，切到竞技环境时退出。详情页以宝可梦名称为标题，来源、范围和对比置于卡片顶部控制带，赛制仍在身份区域切换。说明挂到 body 并按视口定位，避免被卡片裁切；正文只保留来源、差值读法和样本门槛。

对比是双向的：每项只有一条带两侧数值的记录，竞技环境页显示“本视图减官方数据”，官方数据页显示其相反数，读法与变化列“本期减窗口首期”一致；官方数据页打开对比时由对比列替换变化列，不新增列。竞技环境页默认开对比，官方数据页默认关。赛季口径对比同赛季的官方数据；规则口径对比当前的官方数据，两边时间范围不同，样本行会写明。样本少于 5 时不出差值：竞技环境页印计数 `k/n`，只标“外”（官方前十外），官方数据页印对方计数，按官方占比几乎不可能缺席时再标；5–29 显示占比，差值落入 Wilson 95% 区间时淡显。官方只知上界的项印 `≥` 下界，绝不按 0 相减。面板表头用文字写样本（“597 套配置 · 较官方数据”“3 套配置 · 计数”），不印裸露的 n。只有名次的面板（物种排名、队友）比名次。排名角标保留 S（1–10）/ A（11–30）/ B（31–60）/ C（61–100）/ D（101+）五级：数字和底色保持中性且清晰，只在左侧细条上使用逐级减弱的紫蓝过渡，101+近中性。名次差以青绿表示上升、珊瑚红表示下降，不设黄色中间态；1–9 名只给箭头着色，10–29 名箭头与数字同色，30 名及以上才增加极淡底色，不变显示中性横线。误差内差值减弱方向色但保留幅度层级。占比在属性旁以中性数字显示，不叠加第三种色牌。详情面板的百分点差保留自己的色阶，不与名次差的阈值和样式耦合。亮暗主题分别适配文字与底色。详情页的来源、范围、样本与对比控件整合在使用率卡的顶部控制带，分享图不含交互控制带。

竞技环境由谁构成写在说明里（单打主要是天梯上位构筑，双打主要是线上赛事报名队伍），不按证据类别另拆子视图。榜单卡片的竞技环境占比放在属性图标旁，不加行、不加进度线，两个数据源的卡片尺寸一致。分享图的画框印出总体、口径和样本数，截图离开页面后不能被读成官方数据。竞技环境详情页只显示前十位队友；队友条目至少来自 3 个不同队伍单位才进 projection——更少就接近公开一支队伍的阵容；其余面板不设门槛。击倒数据是官方全分段遥测，没有竞技环境对应物，竞技环境视图不显示击倒卡。

全局排名趋势是环境页的第二个视图：页头的“排名｜趋势图”切换，状态在 URL（`?view=trend`；旧的 `/trend` 与 `?trend=1` 仍然打开它）。图保持原尺寸、占正文列宽，不以排名表替代图；窄屏保留图并在图自己的区域内横向滚动，不撑宽页面。视图代码、图表代码和趋势 DTO 在首次切换到趋势后才加载。图上的名称链接到同一赛制的环境详情；页头的单打／双打切换同时作用于排名与趋势。

### 7.1.2 图鉴浏览筛选

图鉴四个 tab 的搜索与筛选收在同一条页边栏里，并**随 tab 整套切换**：命中区间对特性列表没有意义，
所以它在那里根本不出现（特性只有搜索，不设筛选块）。每个 tab 各自持有自己的搜索词与筛选条件，
来回切换不清空。

图鉴的宝可梦卡与榜单卡是同一种卡、同一套网格，全国编号占榜单放名次的那个角标位：两页切换时每张卡的
尺寸与位置都不动，视线不用重新找。名字框恒占两行——网格行高取同行最高者，一个折行的形态名会把整行抬高
一行的高度，而单打/双打切换重排的恰好就是长名字的落点。

宝可梦与招式两个 tab 共用同一行属性选择器，但**语义不同且必须写在界面上**，不能让读者靠猜：

- 宝可梦：属性取**交集**。选水+飞行问的是双属性，这是两个选择唯一有用的读法；因此选三个属性必然为空，
  那是关于 roster 的真实回答，空结果照常显示，不得偷偷改判为并集。
- 招式：属性取**并集**。选火+水就是同时看这两科。

取消选择就是再点一次，因此属性行不带清除按钮；两种语义也不在行内印字。

宝可梦另有特性（单选）、招式（多选，取交集＝全部学会）与种族值。边栏有纵向空间，特性与招式因此是
可搜索的勾选列表而不是输入联想：候选摆在眼前才谈得上挑，输入框只能盲打。种族值仍是小型表达式而不是
六组滑块：`spe>=100 bst<550` 精确表达意图、任意组合无需为每种组合做 UI，更重要的是**能报出没看懂的
部分**——已理解的条件照常生效，未解析 token 让输入框转为 invalid 态并在 title 里点名，绝不静默忽略
（同 team `unresolved_conditions` 的纪律）。

招式另有物理/特殊/变化分类与威力、命中、PP、先制四条区间。区间是两个可空数字框而不是滑块：空的一端
表示"不设界"，滑块说不出这句话。先制的格档取自数据里真实出现的值，不铺一行 -7..+5 的固定档位去提供
永远为空的选项。道具按数据自带的自然分类筛，不另造一套分类。

招式筛选依赖 `dex/learners.json` 这份倒排索引：逐只 learnset 是懒加载的，客户端自行聚合"谁会击掌奇袭"
会退化成按 roster 逐个请求。索引只在真的用到招式条件时才取。索引未到达前返回空列表而非未过滤全集——
闪一下错误答案比空列表更糟。

### 7.1.3 计算页配置抽屉

计算页复用图鉴的宝可梦搜索和筛选轴，但结果名称只控制单项展开，不直接改动计算输入。抽屉一次只展开
一只；其真实联合配置与 Meta 回填按需读取，空白自定义项不依赖配置请求成功。各子页独立选择填入方向，
满额时明确拒绝，不覆盖已有配置。抽屉搜索和空白卡片编辑不得触发
伤害或速度批量计算；速度线按自身输入签名重算，标签页隐藏时推迟到再次显示。

实际配置对位页复用同一搜索、筛选和联合配置卡，但只有“我方配置”一个填入方向，因此不显示方向开关；每次计算存为运行记录（§2.3），输入区头部的“历史计算”与“导入队伍”并列，选中即载回当时的队伍与结果，数据已更新时结果上方提示并可重算。
它遵守该页最多六个待比较配置（一支队伍）的上限，也可以从资料库直接导入一支当前赛制的队伍；切换
单打／双打时按新赛制重新读取展开项。存储页的检索也是这个抽屉，但填入方向是宝可梦箱：抽屉顶部选
环境配置的赛制和放入的箱子，选中的配置或自定义放进该箱的下一个空格（满了顺延），不跳转环境页。
速度线环境表的格子不是填入入口：格子只给悬浮提示，配置只经抽屉或队伍条进入队伍。

凡是手动输入技能、道具、性格的位置（计算页各标签、实际配置、存储页与资料库面板的配置编辑），选项先列
该宝可梦在环境详情里的常用项（各面板前十），按使用率从高到低并标出占比；其余性格按增加的能力分组，依次为
攻击、防御、特攻、特防、速度，组内按减少的能力排序，不加不减的五种统一排最后。招式保留原顺序，道具保留分类顺序。
箱子里的宝可梦不属于任何赛制，取单打、双打中较高的占比。特性与 SP 不排序。使用率只来自已上榜物种的
环境详情，未上榜的物种不发请求；Mega 读其原种。图鉴名称对应到榜单的实际 slug，不假定两个数据源的标点编码相同。

宝可梦名称输入共用本地词表候选，保持图鉴顺序，不随环境名次重排。候选顶部始终显示紧凑的属性图标按钮；
连续点选多个属性取交集，可与三语名称搜索叠加。再次点击取消，一键清除后恢复完整列表。筛选不请求环境数据，长列表只渲染视口附近的行。

### 7.1.4 配置反推

计算页的“配置反推”用实战里看到的伤害收窄对方配置：每条观测是一次命中（我方打对方看对方剩余百分比，或
对方打我方看我方剩余 HP），录入时冻结当时的双方配置与场地条件。游戏内对方血量只显示整数百分比，取
floor，未倒下时最少 1%；我方 HP 精确。

伤害状态空间是对方的性格、道具、特性与 HP / Atk / Def / SpA / SpD 的 SP（每项 0–32，合计不超过 66）。性格、道具、特性取环境前十面板中使用率不低于 1% 的项；SP 不剪枝。确认的道具与特性可以覆盖环境候选，Mega 固定形态与进化石。速度使用相同的候选范围：对每个可行性格、道具与特性组合，将剩余联合 SP 预算投影为速度 SP 上限，初始也直接显示范围内的可能值。速度投影不改变既有五个伤害轴的组合数与性格权重口径。详情在耐久与攻击之间显示速度泳道，复用速度线的输入映射与引擎，计入当前能力等级、异常状态和战场，标出我方当前速度；泳道表示边界，不保证其间每个整数速度均可达。

每个联合状态的权重为性格、道具和特性的先验乘以各次命中可解释乱数的比例；各轴按总预算内其它维度的数量与权重边际化。攻击与防御两侧均把道具交给引擎；满血气势披带/结实按存活截断读数处理，不能把 1% 当成一个精确伤害乱数。单条对所有候选都不可能的观测标为无效并给出相邻可行读数，不参与收窄；各自可行但彼此冲突的记录保留，显示空集合。旧记录缺少冻结配置、当前对方已切换战斗形态、引擎拒绝或模型不支持的命中均明确跳过。我方成员离队不删除已有冻结记录。

性格初始显示环境使用率；有有效观测后，按剩余联合配置的权重边际化并归一化显示观测后相对占比。该比例只适用于当前候选范围与 SP 模型，不表示真实性格已确认；计算中、失败或零总权重时不显示比例。排除的性格保留在同一区域并加删除线。

只要有可行组合，就提供一套默认折叠的具体配置示例：优先从符合当前候选条件和全部有效观测的常见配置中选环境占比最高者，否则展示剩余联合状态中权重最大的一套（相同权重时按环境常见 SP 模板的最小差异选取）。模型示例的速度投入参考环境模板，但受剩余联合 SP 预算限制，六项合计合法；该具体 SP 分配没有环境出现率证据，也不是唯一推断结果。示例不表示已确认的实战配置，也不自动写回队伍。计算器实际配置仍是四个工具共享的输入，只独立核对能否解释有效观测，其性格和 SP 不作为反推约束。

推断与历史边际在独立 worker 执行；反推伤害请求使用独立的引擎 worker 池（按设备核数至多 3 个，已有引擎都忙时才增开），小批次按序分发、观测优先，过时任务停止分发后续批次，隐藏标签停止新请求与推断。结果只接受当前输入对应的任务。多段攻击、未知 HP/速度轴决定威力或多回合累积的招式不作精确反推；范围技可记录单次命中并标明单目标，两目标联合观测与环境长尾留给后续版本。

### 7.2 事实问答

在线 QA 是无历史的单次请求。模型只能通过白名单只读工具获取 dex、meta、公开联合聚合和伤害/速度事实；工具和 provider 结果均有结构、轮数、字节、token 与时间上限。未获工具事实时不得把模型记忆表述为项目事实。流式请求在每轮开始和每次工具调用后推送一次 `report`（`QaProgressDto`：目前为止的 `toolTrace` 与轮次），内容不超出最终 `toolTrace` 的披露范围；页面据此实时列出已查询的数据。问答记录只在浏览器（§2.3 运行记录），由输入区的“记录”按钮打开一个浮层：左侧按日分组、可搜索、方向键切换，右侧预览所选问答，回车打开到页面；平时不占版面，窄屏只显示列表。

在线版把问答、建队向导和确定性的队伍诊断收在“辅助”页面，问答是默认子页；诊断不耗模型额度，可选的 AI 解读留在报告内。存储页与建队结果的“诊断这支队伍”带着队伍切到这个子页。辅助入口在 `llm.qa`、`llm.builder` 或 `team.validate` 任一可用时出现；诊断单独由 `team.validate` 门控，不依赖模型 provider。各子页保留自己的 capability 门控、浏览器会话草稿和本地运行记录，不因切换标签取消在途任务。建队与诊断的记录以“队伍卡片条”列在输入区上方，选中记录时输入区折叠为一行条件摘要，可展开修改或按原条件重跑。顶栏导航依次为 环境 / 图鉴 / 计算 / 模拟 / 辅助 / 存储（各页标题为 环境模拟、AI 辅助、宝可梦存储；存储页路由仍是 `/teams`）。模拟页与辅助页的页头只把标题与标签吸顶，说明文字随页面滚动。

provider key 只在服务端。模型、base URL 和额度由部署配置决定。MiMo 问答单独使用 `PCUI_MIMO_QA_MODEL`，建队和诊断解读使用 `PCUI_MIMO_MODEL`，两路各自保留原 provider 的 DeepSeek 回退。回答使用英文 canonical 实体和界面语言 prose；配置缺省须披露来源与假设。伤害与速度工具默认取环境各项众数组成的常见配置假设；完整使用率配分未列出的 SP 轴为 0，已知的 0 与未知配分分开处理。持有自身超级石的一方按进化后的形态与特性计算（规则同 team 技能的 dex `mega_forms`），被问的超级形态始终按超级形态计算。

速度线默认比较对手的常见配置与被问者的实战速度分布。被问者只统计真实队行中同时已知性格、速度 SP 与道具的配置，性格只认 dex 名称或别名的精确匹配；最多读取 1500 队，至少 5 条有效速度样本才形成分布，并披露样本数、截断读取与无法解析的性格。“稳定更快／更慢”指该对手常见配置快过／慢于至少 90% 的被问者有效样本；“通常更快／更慢”阈值为 60%，“通常同速”阈值为 50%，阈值按未取整的样本数判断。同速不算更快。数据缺失、样本不足或读取失败时仅比较常见配置，不能补造分布或声称稳定。只有用户明确询问对手自身的速度范围时才追加配置簇包络与覆盖率；包络是否重叠作为独立关系，不替代上述比例判定。上述判断不包含顺风、戏法空间、天气／场地加速、轻装、麻痹、能力等级等临场变化。🚩 真实队库中很多行没有速度 SP，有效样本可能远少于匹配队伍数；“稳定”限定为当前对手配置相对这些样本的统计关系，不代表对手所有配置或完整天梯总体。

常见配置与速度分布在进程内按数据快照（skills 根的真实路径与 meta、真实队库、dex 数据目录的文件状态）、赛制和名称缓存，只缓存确定的结果。首页与问答页共用 `qa.ex1/2/3` 三语示例，方向是跨数据源做一次用户不愿手工完成的组合判断。点示例只把问题填进输入框，发送仍由用户决定（发送消耗模型额度）。预算先预留、后按真实 usage 结算；用户次数退还与 token 结算是两个独立动作。

### 7.3 简化建队向导

在线向导是一屏输入、一支候选、确定性校验和最终披露，不提供本地 UEP 的候选比较、循环对话或中途 checkpoint：

```text
normalize -> audit/intake -> frame + grounding -> LLM assembly
 -> validate + slate -> direct checkpoint -> draft + answer-audit
```

表单与 profile 默认须覆盖 intake catalog；ID 漂移必须 fail loud。anchor、owned 和 avoid 先经 dex 归一。模型的选材宇宙来自 frame、公开 detail 和明确 Mega options；item/ability/nature/moves/SP 保持联合关系，不能拼接 meta 边际。

模型输出经名称归一和确定性清理后再过 skill gate。Mega 登记数量跟随所选 frame 中登记数已知的参考样本或用户明确约束，未知配置不计为零，也不固定为某个数量；slate 已知缺少众数方案时先修复，再进入最终复核，修复输入保留对应分布与门禁原因。战术偏好由模型落实到最终配置，frame 不声称已按偏好筛选。tradeoff、偏离、Mega 与对位说明必须引用 slate/audit 事实。guaranteed-OHKO 暴露按 `guaranteed-ohko-impact-v1` 的稳定事实顺序展示完整路线；它只定位本次电池里影响最广的确定 OHKO，不是强度排名。

`web_jobs` 只在任务期间保存重放所需工件和进度；完成、取消或过期后删除。浏览器把每次建队存为运行记录（条件、各 gate 的状态与详情、结果），运行中的任务凭 job id 在刷新后继续跟踪。进度按 gate 的真实状态展示：左侧六步，各步标明读取的数据来源，完成后写出该步的实际产出（补齐的默认项、参考框架数、读取环境数据的宝可梦、选出的六只、规则校验、复核）；右侧装配台依次出现条件、候选池和填入六个格位的队伍。完成后这一视图折叠在结果下方。结果中的环境威胁与诊断的应对表一致：先给分级计数，默认展开列出前三个威胁，其余一键展开。

### 7.4 限流、预算与隐私

在线服务使用签名设备 cookie 与不可逆短期 IP 身份，不保存原始 IP。QA、builder、diagnose 和确定性接口分别计数与限并发；模型任务和 CPU 任务使用不同 lane。Nginx 与应用层都限制速率、体积、条数和超时。

额度和预算在服务端原子处理，具体数值只在配置和 quota 响应中维护。quota 响应另带 `access`（`visitor` / `authorized`：owner、tester、smoke 与本地不计量演练），供只在浏览器里执行的配额使用，如资料库容量（§2.3）；它描述身份类别，不是凭据。模型预算只影响 LLM；静态浏览、浏览器计算和已生成的确定性报告不依赖它。日预算耗尽时，问答以类型化的 `budget_exhausted` 拒绝，页面给出恢复时间（UTC 日界）与不耗模型额度的入口；建队向导改跑 context / frame / ground 三个确定性 gate，以 `preview`（参考骨架与候选范围）结束，按一次普通建队计数，不组装成队、不经 slate，也不以建队结果呈现；诊断照常返回报告，只缺 AI 解读。页面按错误码分支，不解析消息文本。正文不进应用日志，短期任务和计数按生命周期清理。验证码只能是附加门，不能替代预算断路器与端点校验。

计数端点（QA、builder、diagnose、实际对位、tune）的每次请求记一行访问日志（`access-log.db`，与 `online.db` 分库）：身份类别、tester key id、设备摘要、按日轮换的网络摘要、路由、结局（流式答案取终止事件的 status 与错误码）和耗时；不记请求正文、答案和原始 IP，页面加载时的 quota 读取也不记。保留期按身份类别：访客与 owner 90 天、部署 smoke 14 天、tester 永久——它是一份发给具体个人的凭据的核查记录。tester key 自身另有只增不删的事件记录（创建、轮换、预算与使用人变更、首次绑定、换设备或旧 token 被拒、预算耗尽、每次模型花费、移除），key 移除后仍保留；`holder` 字段手工记录实际使用人。

授权旁路对**所有**计数端点一致生效，管线本身完全不变，真实 token 消耗仍进入总账。服务端仍为每个浏览器签发 HttpOnly 签名设备 cookie；owner dev key 只做恒定时间凭据校验，不绑定设备，因此可在 owner 的多台设备上复用。tester key 在第一次成功请求时绑定该 cookie，服务端只持久化凭据和设备标识的摘要；它可独立创建、轮换、移除，并分别配置 UTC 每日 token 预算与累计总预算（累计用量记在 key 上，跨日且轮换不清零），缺省均为无限，且不获得调试字段。清除站点 cookie、复制已绑定 tester key 到另一设备或复用已轮换 tester key 都不能继续旁路。设备绑定不是硬件证明：首次使用前转发 tester key，或连同完整浏览器资料复制，仍不能由服务端可靠区分；轮换、移除和费用上限负责控制这类残余风险。

🚩 发布 smoke 与浏览器凭据严格分离：`PCUI_SMOKE_KEY` 是不绑定 cookie、不得分发的运维凭据，只用于 deploy observe 和基准工具。浏览器 dev key 不能兼作 smoke，避免把可交互 owner 凭据扩散到自动化环境。新增计数端点必须同时接入 visitor、browser-access 与 smoke 三种路径，不能只接 QA 和 builder。

### 7.5 确定性接口与队伍诊断

capability 负责入口发现，服务端仍独立执行白名单、上限、超时和并发控制。自由文本队伍按 team-json/Showdown、已知分享格式、species-only 三层解析，再统一经 dex canonicalize；不完整结论标为 partial/unknown。

诊断运行 validate、diagnose 和受限 check coverage，再映射为披露安全 DTO。候选直接回流时按最终配置计算，不退化成物种列表；确定性修正改变配置后，解释必须基于修正版重新生成。

`POST /api/team/matchup` 接受结构化队伍或受限文本，返回同一次计算产生的 summary、明细和规范化队伍；一次最多六个配置（一支队伍）。Top-K 在 team 合法范围内由消费端指定。公开端按 workload units、队列和确定性 semaphore 公平限额，不消耗模型额度。

`POST /api/team/tune` 只接受无路径 team-json 和有界 benchmarks，通过公开 `session` 算子运行。额度在廉价形状校验后预扣，失败按既定语义退还；返回的 cliff cards 才是精确结果。

roles 的公开值表达注意等级，不是强制模板。AI 解读是确定性报告上的可选单次调用，失败只增加 `explanationError`，不能改变报告事实。诊断没有中间事件：进度页的前两步按时钟推进，报告到达即全部完成，可选的 AI 解读另列一步；报告顶部是由报告本身计数的摘要（合法性、环境应对、集中弱点、打点盲区、速度区间、功能覆盖），其下为分区卡片。

🚩 公网 CDN 会掐断**十秒内没有产生任何字节**的回源连接（源站只看到 nginx 499，浏览器只看到一次网络失败，而服务端往往已经算完）。诊断、实际对位、tune 与 QA 都可能跑十几到几十秒，因此凡是可能超过该窗口的在线端点，都要在 `Accept: application/x-ndjson` 下改用事件流：**第一个字节在开工之前发出**，之后以远小于该窗口的间隔发心跳，最终事件才带结果，HTTP 错误语义以 `error` 事件的 status 透传。首字节不能只靠响应头——中间件会把响应头压到第一个 body chunk 一起发。心跳间隔大于该窗口等于没有心跳。

## §8 部署

在线拓扑为同源静态站与单 worker API：

```text
Nginx
  ├─ SPA dist + projection
  └─ /api -> FastAPI -> restricted LLM / deterministic workers
```

服务使用独立系统用户、venv、systemd unit、SQLite 和私有 env。release 目录只读；随 skill 发布的 dex SQLite 只读，只有主机状态目录可写。

`dist/projection/bridge/skills` 是不可变发布集，`data/env/venv` 是主机状态。发布以完整目录原子切换并保留可验证回滚，不能分别更新前端、投影或 skill。主机、证书、防火墙和密钥属于部署配置。

### §8.1 更新、构建、部署与发布自动化

`dev/update/` 更新数据，`dev/deploy/` 构建并切换不可变 release，`dev/release/` 发布 Git 与 rolling assets。三者共享 commit/manifest 身份，但默认互不触发、分别授权。

长期不变量：

1. 正式输入绑定 clean commit；dirty 仅允许本地预览。
2. 一次构建、一份 SPA；runtime 差异只由配置、capabilities 和 adapter 决定。
3. dist、projection、bridge、skills、calc 与部署配置由 `deploymentId` 和逐文件摘要原子绑定。
4. projection 按对象结构审计，拒绝 raw team、build-state、quarantine、PII 和可还原整队数据。
5. 候选须过本地/online-echo 验收与目标主机 preflight，观察失败只在 live 仍指向该候选时回滚。
6. 不可变内容与主机状态分离；数据库迁移先备份并声明回滚兼容性。
7. deploy、run、dev/public publication 分别写机器 receipt；动态数字只留在 receipt/配置。
8. public 发布从白名单重装配；rolling assets 的省略不能隐式删除其他资产族。

操作以 [`../dev/deploy/README.md`](../dev/deploy/README.md)、[`../dev/release/README.md`](../dev/release/README.md) 和 CLI `--help` 为准。

## §9 成本与容量

费用和容量以 provider usage、benchmark receipt 和主机观测为准，不在设计文档维护单价、请求次数或一次跑数。

- LLM 请求先按场景预留上限，结束后按真实 usage 结算；日预算是总断路器。
- QA、builder、诊断解读和确定性 lane 分别记录成功率、延迟、资源与缓存指标。
- 配置、prompt、工具面或进程模型发生承重变化后重跑固定基准。
- 静态浏览与客户端计算不计模型预算；确定性服务按 CPU、内存和并发独立定容。

### 9.1 确定性通道的定容模型

每个在飞 `team.py session` 是独立进程树，请求间不共享内存；总内存随并发近似线性，CPU 随工作量增长。稳态并发由核数、每请求 RSS 和延迟共同约束，不能只靠增加 semaphore 或内存推高。

具体宽度必须在目标主机上用 capacity benchmark 测量。超过有效核数通常只增加排队和上下文切换；静态内容应尽量卸给 CDN/浏览器，使主机资源留给确定性工作。跨主机 CPU 指数只作粗估，不能替代现场测量。

### 9.2 计算引擎宿主形态

NCP 可由进程内 quickjs-ng、常驻 Node 或 Node one-shot 承载。无 Node 的生产主机上 quickjs-ng 是硬依赖，不是可选加速；preflight 必须单独检查。宿主选择是常驻内存、调用开销和依赖的取舍，批处理会摊薄微基准差异，最终以实际 workload benchmark 决定。

## §10 技术选择

前端使用 React、Vite、TypeScript、Zod 与 Dexie（浏览器资料库）；图表自绘 SVG，不引图表库；本地/在线 API 使用 FastAPI、uvicorn 与 SQLite；本地 companion 经 pipx/wheel 分发。版本只在 lock files 固定，升级由类型、契约、构建和浏览器测试判定。

浏览器 worker、provider、bridge worker 和 store 可以替换，但必须保持 §2 的 adapter、DTO、Build-once 和身份绑定。

## §11 仓库与发布边界

`frontend/web`、`frontend/bridge` 与 `frontend/protocol` 在本仓库共同演进；四个 skill 独立发布。Web 发布物包括同一 dist 的本地 UI、dist + projection + online bridge 的在线集，以及绑定发布身份的图片/数据资产。

协议稳定前不拆仓。任何拆分都必须保持 raw skill -> mapper -> Web DTO 单向依赖与跨仓兼容测试。

## §12 图片资产

位图 pack 使用内容寻址文件和 manifest；原创图标、placeholder 与品牌 PNG 随 UI bundle。完整 manifest
是哈希、尺寸与 provenance 的审计权威；projection 从中机械生成只含 key/match/path 的 `runtime.json`，
浏览器 resolver 只读取该紧凑索引，以 dex canonical slug 为主键，不另造图片身份或路径规则。

resolver 返回 `exact`、`base_fallback` 或 `placeholder`。形态页不得把 base fallback 伪装成 exact；无法确认时用占位图。第三方图片记录 provider、URL/revision、获取时间和 rights note；运行时不热链。新增来源或 roster 变化后重建并校验，不得 fuzzy 猜图。发布用 pack 必须与当前 dex canonical Pokémon/item 集合精确相等，每个 payload 的 size/hash 复验通过；projection 构建同时要求当前 rule 的 single/double opponent cache 都存在、非空且源指纹有效。

## §13 开放问题与准入条件

- 验证码只能在预算和端点防护完整后作为超额附加门。
- session store 继续使用整会话 revision CAS；只有 artifact 依赖形成可验证契约后才评估细粒度合并。
- team 常驻 worker 只有在固定基准证明冷启动是主要瓶颈、skill 先定义正式 `serve` 契约，并完成请求状态、数据代际、池宽与内存审计后才准入；builder 不能以自身长延迟作为理由。
- 队伍/诊断中的计算器 hand-off 必须携带可复算 team、move、conditions 和 evidence；前端只预填，不将摘要升级为精确结论。
- 拆分 Web 仓库须先满足 §11 的单向依赖与跨仓契约门。
