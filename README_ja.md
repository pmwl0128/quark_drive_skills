Quark Drive Skills は『ポケモンチャンピオンズ』向けの4つのAgent Skillsをまとめたパッケージです。任意で利用できるブラウザ版は **Quark Drive Web** と呼び、同じリポジトリで配布しています。AIアシスタントから次の作業を行えます。

- 対戦図鑑の確定情報を調べる
- 現在および過去シーズンの環境分布を確認する
- ダメージ、確定数、耐久、素早さラインを計算する
- 根拠を残しながら構築、添削、変更、選出検討、SP調整を進める

4つのスキルは同列にインストールされ、それぞれ独立して呼び出されます。`pokemon-champions-team` は構築全体を扱う際に残り3つを連携させますが、図鑑確認、採用率調査、単発計算までteamスキルを経由させるわけではありません。

通常の問い合わせは同梱データをローカルで参照します。このプロジェクトが目指すのは構築の強さを単一スコアで表すことではなく、AIが使った事実、計算条件、前提、トレードオフを追跡できる状態にすることです。

## プロジェクトの位置付け

| できること | 想定していないこと |
|---|---|
| Claude Code、Codexなどに導入するローカルスキル一式 | Webアカウントや画面を必須とするサービス |
| 図鑑、環境、計算、実在構築データへの構造化アクセス | モデルの記憶だけで答える百科事典チャット |
| ルール適合性、根拠、信頼度、監査手順を備えた構築支援 | 「客観的な最強構築」を返すブラックボックス最適化 |
| シーズンとレギュレーションが明示された更新可能なスナップショット | 日付を意識せず使える常時リアルタイムDB |

スクリプトが担当するのは事実、計算、ルールに基づく確認です。目的の解釈、候補の設計、取捨選択、最終的な説明はAIモデルが担います。この役割分担がプロジェクト全体の基本方針です。

### Quark Drive Web：ブラウザで使える補助ツール

4つのスキルはAIアシスタントのCLIからすべて利用できます。データ、構成情報、生成過程をより直感的に確認できるよう、任意のコンパニオンブラウザ画面も用意されています。図鑑や環境スナップショットを視覚的に閲覧し、対面、ダメージ、素早さ、調整、構築診断を補助します。

- **オンライン版：**[champion.mpan.top](https://champion.mpan.top) をインストール不要で利用できます。リソース制約のため、オンライン版の一部機能はローカル版より簡略化されています。
- **ローカル版：**[`data-latest` Release](https://github.com/pmwl0128/quark_drive_skills/releases/tag/data-latest) から [`Quark_Drive_Web.zip`](https://github.com/pmwl0128/quark_drive_skills/releases/download/data-latest/Quark_Drive_Web.zip) を取得します。ビルド済みパッケージにはPython 3.10+と同梱の実行時依存パッケージが必要です。通常の閲覧と計算にはNode.js、アカウント、モデルAPIキーは不要です。

この画面はスキルの前提条件ではなく、AIアシスタントとの完全なローカル協調フローを置き換えるものでもありません。機能差、依存関係、使用方法は[Quark Drive Web](#quark-drive-web)を参照してください。

> [!NOTE]
> **対応データは『ポケモンチャンピオンズ』に限られます。**
>
> 4つのスキルが正式に対応するのは、現行の『ポケモンチャンピオンズ』で実装済みのポケモン、フォルム、技、道具、特性、ルールです。過去シーズンの検索もチャンピオンズ内のスナップショットです。『ポケットモンスター ソード・シールド』『スカーレット・バイオレット』など本編シリーズのデータや、未実装情報は対象外です。同名のポケモンや技でも、種族値、威力、特性、習得技、仕様が本編と異なる場合があります。検索と計算ではチャンピオンズ現行値を優先します。

## `pokemon-champions-dex`

パッケージ全体の名称解決も担当する、オフライン対戦図鑑です。ポケモンとフォルム、タイプ、種族値、特性、習得技、技、道具、性格、メガストーンの対応を収録し、一括検索と複数条件の逆引きに対応します。

**得意なこと：**

- 中国語・英語・日本語の名称、一般的な別名、多言語のメガシンカ表記を同一データへ解決する
- 貼り付けた構築、所持ポケモン一覧、技構成をまとめて正規化する
- 「この技を覚えるポケモン」「タイプ・特性・素早さ条件を同時に満たす候補」を逆引きする
- meta、calculator、teamで共通利用する正規英名を提供する

**注意点：** 図鑑に存在する、または習得可能であるという事実は、環境で一般的であることや採用価値を保証しません。

質問例：

```text
ガブリアスはれいとうパンチを覚えますか？
だいちのちからを覚えるフェアリータイプは誰ですか？
メガリザードンXの種族値と特性を教えてください。
このメガストーンは誰に対応していますか？
```

## `pokemon-champions-meta`

実際の採用状況を調べるための、オフライン優先の環境スナップショットです。season、rule、シングル／ダブルを分離し、ランキングのほか、技、道具、特性、性格、相方、SP分布の詳細パネルを提供します。

**得意なこと：**

- シングルまたはダブルの上位環境を一覧する
- 特定ポケモンの一般的な採用技、道具、特性、性格、相方を確認する
- 技や道具、条件から採用ポケモンを逆引きする
- シングルとダブルの傾向を比較する
- 前回スナップショットとの差分を事実表として確認する

**注意点：** 詳細パネルの技、道具、特性、性格、相方、SPは、多くの場合それぞれ独立した周辺分布です。各欄の1位を組み合わせても、実在する1つの型になるとは限りません。また、採用率は強さの証明ではありません。

質問例：

```text
現在のダブルで採用率上位20体を教えてください。
メガメタグロスの採用技はシングルとダブルでどう違いますか？
今回の更新で順位や道具採用率が大きく変わったポケモンは？
ダブルの追い風要員は誰と組まれることが多いですか？
```

最新の3種類の単言語ワークブック（`workbook_{zh,ja,en}.xlsx`。シングル／ダブルの全表と事実ベースの更新レポートを収録）は、固定ファイル名で [data-latest リリース](https://github.com/pmwl0128/quark_drive_skills/releases/tag/data-latest)に公開され、リリースごとに置き換えられます。スクリプトを実行せずに閲覧できます。スナップショット日付はシート冒頭で確認してください。

## `ncp-damage-calculator`

同梱のNCP VGC Damage Calculator coreを使用する、『ポケモンチャンピオンズ』用ダメージ・素早さ計算スキルです。攻撃側と防御側のSP、性格、道具、特性、ランク補正、技、場の状態を指定し、全乱数、割合、確定数、耐久結果、行動順を返します。

**得意なこと：**

- 特定攻撃のダメージ範囲と確定1発／2発ラインを計算する
- 指定した型が攻撃を耐えるか確認する
- 2体の完全な素早さ状態を比較する
- 追い風、トリックルーム、こだわりスカーフ、天候込みの素早さラインを調べる
- teamスキルの対面評価とSP調整に厳密な計算結果を提供する

**注意点：** 計算に成功しても、その型がチャンピオンズのルールに適合するとは限りません。また、完全なターンシミュレーターではないため、回復の反復、状態変化、PP、非公開情報、双方の選択分岐までは扱いません。未指定の型や場の条件は前提として明示する必要があります。

質問例：

```text
いじっぱり攻撃SP32のメガメタグロスが使うじしんは、このメガライチュウYにどれくらい入りますか？
このガオガエンは一般的なガブリアスのじしんを確定で耐えますか？
追い風下ではどちらが先ですか？トリックルームだと順番は変わりますか？
目標を抜くには素早さSPがあといくつ必要ですか？
```

## `pokemon-champions-team`

構築全体を扱う専用スキルです。新規構築、未完成構築の補完、ルール適合性の確認、構造診断、環境への対面確認、選出検討、メンバー変更、SP調整を担当します。残り3つのスキルと同列に配布されますが、構築タスクの内部では図鑑情報、環境データ、厳密計算を1つの監査可能な流れへまとめます。

単に一言からそれらしい6体を返すジェネレーターではありません。ユーザーの意図、現行環境、実在する同時採用データ、再計算可能な対面情報をもとに、単一の合成スコアに頼らず、説明可能な提案を作るためのスキルです。

> [!IMPORTANT]
> **AIによる構築回答の最低品質を底上げしますが、上級者の構築経験そのものを代替するものではありません。**
>
> 古い記憶、名称の取り違え、ルール違反の型、計算ミス、独立した採用率から作った架空の型、ユーザー条件の見落としを減らし、事実確認と推論手順を安定させます。一方、候補の質や説明の深さは、スキルを動かすモデルによって変わります。実際の操作感、選出傾向、想定相手、試合中のプランに構築が合うかどうかは、ユーザーから与えられる対戦情報にも左右されます。

最初の出力を自動生成された最適解とは考えないでください。より良い結果を得るには、狙っている勝ち筋、基本選出や初手、よく当たる相手、許容できる弱点、実戦で負けた場面、すでに持っている人間側の知見を伝えることが重要です。まず根拠付きの案を作り、実戦やリプレイで問題を確認し、その内容を返して再調整する使い方が最も効果的です。

### 入力方法

決まったファイル名や、ユーザーが覚えるべきスキーマはありません。次のような入力を利用できます。

- 「このポケモンを軸に組んで」という自然言語の依頼
- Showdown形式の構築テキスト
- 既存のteam JSON
- 各メンバー、技、SPを文章で記したメモ
- 構築や所持一覧を保存した任意のローカルファイル
- エージェントが先に読み取れる鮮明なスクリーンショット
- 「所持ポケモンのみ」「このメガ枠は固定」「トリックルーム禁止」といった条件

エージェントはポケモン、技、道具、特性、性格をdexで解決し、構築情報、ハード制約、ソフトな希望、対面目標を検証可能な構造化入力へ整えます。ユーザー側で形式を加工する必要はありません。

### 機能一覧

| 機能 | teamスキルが行うこと |
|---|---|
| **入力とルール適合性** | AIが文章、画像、ファイルを構造化したチーム入力に整理します。スクリプトはShowdown形式やJSONを読み、名称、使用可能なポケモン、習得技、特性、道具、同種・同一道具制限、登録数、SP、メガシンカの対応を確認します。結果は `valid` / `invalid` / `unknown` を区別します。 |
| **構築診断** | 防御タイプ、攻撃範囲、素早さ構造、S操作、役割に関する客観的な兆候を個別に示し、総合点へまとめません。 |
| **対面と選出** | 現環境の上位に対する双方のダメージ、素早さ、確定数を計算し、シングル6→3、ダブル6→4、1試合1回のメガシンカなど選出時の制約を確認します。「最善選出」を自動決定しません。 |
| **SP調整** | 「Xを耐える」「Yを抜く」「Zを確定1発／2発にする」を明示的な対面目標へ変換し、必要最小SPとその代償を調べます。唯一の最適配分を探索する機能ではありません。 |
| **候補と実在構築データ** | 不足要素から補完・交代候補を探し、変更前後の事実を比較します。実在する同時採用構造、代表的な型、完全な実在構築サンプルを、AIが独自案を組むための根拠として使います。 |
| **結果の検証** | すべての候補に同じ事実確認を行い、ルールや必須条件に反する案を除外します。最終回答の前提、トレードオフ、調整説明、再現できない数値の有無も確認します。 |

### 構築タスクの進み方

内部では「先に感覚で生成し、後から理由を付ける」進め方を避けるため、手順化された検証を行います。ユーザーが各内部コマンドを覚える必要はありません。全体は次の4段階です。

1. **目的を整理する：** ルール、軸、使用可能範囲、固定条件、プレイ方針、必要な対面ラインを確認します。自由度の高い新規構築では少数の質問を分けて行い、既存構築の添削では本当に不足している情報だけを聞きます。
2. **データで裏付ける：** 現行環境と実在構築の両方を確認し、「何が多いか」と「何が実際に同時採用されているか」を分けます。独立した採用率欄から架空の型を作りません。
3. **候補を比較する：** 1つ以上の方向性を作り、同じルール適合性・構造・対面・信頼度チェックを適用します。各変更で何を改善し、何を失うかを示します。
4. **検証して提示する：** 必要なダメージ、素早さ、選出、SPラインを計算し、最終文章の数値、前提、トレードオフを再確認してから、ユーザーが判断・反復できる形で提示します。

手順に従うことで根拠を記録し、条件を確認し、重要な数値を再計算できます。AIには各検証段階を守り、その結果を正確に伝えることが求められます。特定の対戦思想が常に正しいと判定したり、客観的な最適構築として認定したりはしません。

### 主な使い方

| 依頼 | 処理内容 |
|---|---|
| **ゼロから構築する** | 「チーム構築フローを開始して」と言えば完全なガイドへ入ります。通常の構築依頼では不足情報のみを順番に確認し、比較・検証済みの方向性を提示します。 |
| **既存構築を添削・変更する** | 現在の構築を整理し、まずルール適合性と構造を確認します。必要に応じて環境対面を追加し、交代案ごとの改善点と代償を説明します。ユーザーが固定した軸を勝手に外しません。 |
| **選出、対面、SPを詰める** | 内容に応じて6→3/4の選出、環境全体への対面表、具体的な閾値調整を使い分けます。「今の型で耐えるか」と「耐える型へ変更してほしい」を同じ計算として扱いません。 |

### 実在構築データの扱い

配布版には、シーズン、レギュレーション、シングル／ダブルごとに分けた実在構築サンプルが含まれます。価値があるのは**同時採用の事実**です。6体の並び、1体の道具・特性・技・性格・SPが同一の観測セットに由来するか、特定の証拠区分でどの構造が繰り返し現れるかを確認できます。

このライブラリはランキングではありません。

- 戦績、順位、レート、サンプル数を強度スコアへ変換しません
- シングルとダブルを混ぜず、旧レギュレーションを現行証拠へ自動混入させません
- 6体のみ判明しているデータは同時採用の参考にはなりますが、完全な代表型として扱いません
- 標準型キャッシュは低信頼度の参考です。環境分布で補ったSPは観測された配分ではなく推定値として扱い、ユーザーのチームは実際の型で再計算します
- AIは実在する完成構築を資料として読めますが、無断で「推奨構築」として丸写ししません。そのまま採用する場合は、サンプルとの一致、採用理由、検討した変更案を開示します

### 出力の読み方

**ルール適合性は単純な二択ではありません。** `valid` は利用可能な事実に基づく全確認を通過した状態、`invalid` は修正が必要、`unknown` は入力または根拠不足です。不明を適合済みとして扱いません。

**採用率は強さではありません。** ランキング、実在構築での同時採用、戦績タグは別々の観測です。AIはトレードオフを説明したうえで提案できますが、スキルが不透明な総合点へ合成することはありません。

**CHECKラベルは対戦シミュレーターではありません。** C2/C1/C0は、評価対象の型、ダメージ、素早さ、ターン予算に基づく受け出し、対面・死に出し、明確な処理手段なしという関係を表します。積み技、回復、状態異常、PP、長期戦は明示された範囲でのみ注意点として扱われます。

**信頼度も結論の一部です。** 実在する同時採用セット、周辺分布からの補完、標準型キャッシュ、少数サンプル、一部計算失敗では、信頼度と注意事項が異なります。重要な前提は最終回答にも残す必要があります。

### 質問例

```text
現行ルールのダブルチーム構築フローを開始して、必要なことを順番に聞いてください。

メガムクホークを軸にシングルを1案だけ作り、重要なトレードオフを説明してください。

このShowdown構築のルール適合性、構造上の穴、現環境上位20体への対面を確認し、変更案を出してください。

roster.txtにいるポケモンだけでダブルを組んでください。ゲンガーは固定、トリックルームは使いません。

この6体から4体をどう選出しますか？相手によってどの選出軸を変えるべきですか？

指定したガブリアスのじしんをガオガエンが確定で耐えるよう調整し、どのSPを削るか示してください。

AをBへ変更した場合の防御、S操作、環境上の穴を比較してください。採用率だけで判断しないでください。

この2体を含む実在構築の共通構造とバリエーションを調べ、完成構築はそのままコピーしないでください。
```

## 4つのSkillの連携

1つの依頼で複数スキルを使う場合も、事実の担当範囲は明確に分かれます。

```text
ユーザーの自由入力
  ├─ 名称・フォルム・習得技・道具の適合性 ──> dex
  ├─ 現行採用率・各項目の周辺分布 ─────────> meta
  ├─ 条件指定したダメージ・素早さ ─────────> calculator
  └─ 構築意図・候補・診断・調整 ───────────> team
                                             └─ 必要に応じて上の3つを利用
```

たとえば「メガメタグロスを軸にダブル構築を作り、一般的ないのちのたま持ちガブリアスのじしんを耐えるようにしたい」という依頼では、名称とルール適合性、現行採用率、実在構築の構造、候補比較、耐久ライン計算を組み合わせます。「現環境で主流のメガメタグロスのバレットパンチは、一般的なアローラキュウコンを確定1発にできる？」なら図鑑・環境・計算の各スキルを連携させますが、構築フローには入りません。

## Quark Drive Web

付属フロントエンドは、4つのスキルが提供する事実と計算を、閲覧・比較・再確認しやすいワークスペースにまとめます。環境の素早い確認、ポケモンの調査、ダメージと素早さの一括比較、標準型またはカスタム型の対面確認、構築分析結果を別ページへ渡して検証する用途に向いています。中／英／日名は表示時にのみローカライズされます。ページ上部には現在のseason、rule、スナップショット日が表示されるため、環境情報はそのバージョンを基準に判断してください。

プロジェクトにシェルを使えるエージェントが既にいれば、一文でローカル版のダウンロード・インストール・起動を依頼できます。手順は「方法 A — エージェントに導入を依頼」を参照してください。エージェントは `AGENTS.md` / `CLAUDE.md` の「Local Visual Interface」節に従って処理します。

| 機能 | オンライン版 | ローカル版 |
|---|---|---|
| シングル／ダブル順位、詳細、KOパネル、採集時刻を分けた採用率／KO履歴、実構築から集計し公式データと比較する上位環境 | 対応 | 対応 |
| ポケモン・技・道具・特性図鑑と中／英／日検索 | 対応 | 対応 |
| 一括ダメージ、乱数、確定数、素早さライン | ブラウザ内計算 | ブラウザ内計算 |
| 計算ページの検索・絞り込みドロワー、実在する型、Meta補完、空のカスタム型 | 対応 | 対応 |
| 標準型マトリクスと実構成KO／CHECK表 | 対応 | 対応 |
| 簡易耐久計算 | 対応 | 対応 |
| マイチーム、ボックス、計算履歴 | このブラウザに保存 | ローカルのワークスペースフォルダに保存 |
| 正確な`team.tune`閾値調整 | 有効な機能と処理量の上限に従う | 対応 |
| 単発Q&A、簡易構築、診断、任意のAI解説 | 有効なAI機能と1日の利用上限に従う | ローカルAIアシスタントの完全なフローで代替 |
| UEP session/artifactパネル | 非対応 | 対応、作業中のローカルAIアシスタントと協調 |

オンライン構築は固定フォームから1つの結果を返す簡易フローです。ローカルUEPの対話、候補比較、
修正ループ、ファイル連携を置き換えるものではありません。

計算ページのドロワーでは、一度に1匹の型カードを展開し、上部の切り替えで入力先を選びます。素早さラインは双方最大6匹、簡易耐久計算は対象となる攻撃側を最大6匹まで設定できます。上限に達すると追加できない旨を表示します。環境詳細のKO対象・脅威リストは**採用率ではなく順位**です。採集時刻と網羅範囲は採用率の履歴と異なる場合があり、未採集の軸はデータ欠損として表示します。

### オンライン版を使う

[https://champion.mpan.top](https://champion.mpan.top) を開きます。環境・図鑑の閲覧と
ブラウザ計算にはアカウント不要です。Q&A、構築、診断、AI解説は、対応する機能が有効になって
いる場合だけ表示され、残り回数はサービスの応答が基準です。標準型対面表は低信頼度の参考なので、
自分の構築を判断するときは実際の型を入力して再計算してください。

### ビルド済みローカル版を取得する

[`data-latest` Release](https://github.com/pmwl0128/quark_drive_skills/releases/tag/data-latest)
から`Quark_Drive_Web.zip`を取得します。同一リリースのSPA、projection、bridge、4つのskill、
runtime設定、manifestが一体化されています。必要なのはPython 3.10+と固定版
`requirements-runtime.txt`で、Node.jsは不要です。

#### 方法 A — エージェントに導入を依頼（推奨）

プロジェクトにシェルを使えるエージェントが既にいる場合（スキルの導入をエージェントに依頼した、あるいは
このリポジトリの `AGENTS.md` / `CLAUDE.md` をプロジェクトに置いた状態）、そのまま依頼してください。

> `pmwl0128/quark_drive_skills` の `data-latest` リリースからビルド済みローカル版をダウンロードし、`requirements-runtime.txt` をインストールして起動してください。ローカル URL を返してください。

エージェントがzip取得・展開・依存インストール・起動を代行し、一回限りの
`http://127.0.0.1:<port>/#bootstrap=...` URLを返します。詳しい手順は `AGENTS.md` / `CLAUDE.md`
の「Local Visual Interface」節にあるため、コマンドを覚える必要はありません。

#### 方法 B — 手動

展開してフロントエンドのディレクトリに移動した後：

Windows PowerShell：

```powershell
python -m pip install -r requirements-runtime.txt
.\start-local.ps1
```

Linux / macOS：

```bash
python3 -m pip install -r requirements-runtime.txt
chmod +x start-local.sh
./start-local.sh
```

起動時に表示される`http://127.0.0.1:<port>/#bootstrap=...`の完全な一回限りURLを開いてください。
既定ではloopbackだけをlistenします。ポートを変える場合は
`~/.pokemon-champions/pc.env`に`PCUI_LOCAL_PORT`を設定します。ログインURLは一度しか使えません。
別のブラウザで開くときや、サービス再起動で開いていたページが切断されたときは、展開先で
`python bridge/pcui open`を実行すると、再起動せずに新しいURLを取得できます。

ローカル画面で作成したセッションをAIアシスタントに処理させるには、一度だけ
`python bridge/pcui install-agent`を実行します（Codexは`--target codex`）。ローカルのホームにある
「はじめに」に、この端末でそのまま使えるコマンドが表示されます。その後はセッションページの引き継ぎ指示を
アシスタントに送ると、進捗がページにリアルタイムで表示されます。アシスタントからの質問やチェックポイントの判断は
セッションページでそのまま回答でき、待機中のアシスタントは受け取ると自動で続行します。MCP対応のアシスタントは
`python bridge/pcui mcp` で接続することもでき、`python bridge/pcui mcp --print-config` で Claude Code と Codex への登録方法を表示します。

### ソースからビルドする

Python 3.10+と、リリース検証で使うNode.js（現在は22）を用意します。各OSの`build-ui`スクリプトは
`npm ci`、現在のskillからのprojection生成、1回のVite buildを行い、対応する`start-ui`で起動します。
異なるスナップショットの`dist`、projection、bridge、skillを混ぜないでください。identity検査が拒否します。

```powershell
git clone https://github.com/pmwl0128/quark_drive_skills.git
Set-Location .\quark_drive_skills
python -m pip install -r frontend/requirements-ui.txt
.\frontend\build-ui.ps1

```

Linux/macOSでは実行権限を付けた`frontend/build-ui.sh`と`frontend/start-ui.sh`を使います。

### プライバシーと更新

- ローカル版は`127.0.0.1`だけをlistenし、通常の図鑑・環境・計算機能にホスト型モデルのKeyは不要です。
  チーム・ポケモン・計算結果・AIセッションはワークスペースに保存されます（ビルド済み版は
  `~/.pokemon-champions/workspace`、ソース版は起動ディレクトリの`storage`）。ボックスページで変更・移行でき、
  バックアップはローカルサービスを止めてからフォルダごとコピーします。
- オンラインQ&A、構築、診断、実構成対面、AI解説では、該当する入力がオンラインサービスへ送信されます。
  非公開の所持リストや対戦メモはローカル版で扱ってください。
- ビルド済み版はzip全体を新しいディレクトリへ再取得し、動作確認後に旧版を削除します。ワークスペースは
  展開先の外にあるため、旧版を削除してもデータは残ります。旧版の中に置いていた場合は先にボックスページで移行してください。ソース版はpull後に
  build/startスクリプトを再実行し、生成物の一部だけを上書きしないでください。

## 初心者向け：自分の対戦プロジェクトを作る

スキルはグローバルにも導入できますが、継続して構築を調整するなら専用プロジェクトを用意する方が便利です。所持一覧、構築、対戦メモ、エージェント向け指示を同じ場所へ置くことで、次回以降も有用な文脈を引き継げます。

### 1. プロジェクトを作成

```bash
mkdir my-champions
cd my-champions
```

ディレクトリ名は自由です。IDE型エージェントではこのフォルダを開き、CLI型では移動してからClaude CodeまたはCodexを起動します。

### 2. 4つのスキルを導入

対応するAIエージェントを起動したら、エージェントへそのまま次のように依頼してください。

> https://github.com/pmwl0128/quark_drive_skills の4つのスキルを現在のプロジェクトへインストールし、リポジトリに同梱されている`CLAUDE.md`と`AGENTS.md`もプロジェクトディレクトリへ配置してください。`quickjs-ng>=0.15`も導入し、この環境で導入できない場合はNode.jsフォールバックが動作することを確認してください。最後に4つの`SKILL.md`がすべて認識されることを確認し、計算機の`schema`コマンドを1回実行してください。

上記の別の[インストール方法](#インストール)も利用できます。

### 3. 自分のデータを追加（任意）

ファイル名や形式は自由です。

```text
my-champions/
  CLAUDE.md           # 任意
  AGENTS.md           # 任意
  roster.md           # 所持ポケモン
  current-team.txt    # Showdown形式または文章の型メモ
  matchup-notes.md    # 対戦記録、頻出相手、変更案
```

固定スキーマはありません。「`roster.md`のポケモンだけを使う」「`matchup-notes.md`を踏まえて再検討する」のように、エージェントへパスと用途を伝えてください。エージェントが内容を読み取り、正規化してから対応スキルへ渡します。

### 4. 質問し、結果を蓄積する

プロジェクト内でエージェントを起動し、たとえば次のように始めます。

```text
ガブリアスはりゅうのまいを覚えますか？
current-team.txtのルール適合性と環境対面を確認してください。
roster.mdにいるポケモンだけでシングル構築を作ってください。
matchup-notes.mdの負け筋を踏まえて変更し、固定した軸は残してください。
```

構築の各版と対戦メモを残しておくと、毎回空の会話から作り直すよりも、自分のプレイに合った調整を続けやすくなります。

## モデルによるSkill起動と手順実行の差

スキルの自動起動は、エージェントが`SKILL.md`を正しく読み取り、タスク中も指示を維持できることに依存します。すべてのモデルで同じように強制される実行機構ではありません。ツール利用や長い指示の追従が弱いモデルでは、記憶だけで回答する、事実スキルを1つしか呼ばない、teamの内蔵手順を一部省略するといったことがあります。

その場合は、依頼内で明示してください。

```text
最初にpokemon-champions-team/SKILL.mdを読み、teamスキルの完全な手順でこの構築依頼を処理してください。
記憶だけで答えず、名称とルール適合性はdex、採用率はmeta、ダメージと素早さはcalculatorを使ってください。
候補比較、ルール適合性の確認、最終検証を省略せず、teamスキルの内蔵フローに従ってください。
```

同梱の`CLAUDE.md`または`AGENTS.md`をプロジェクト指示として使うと、スキルの振り分けと手順実行が安定しやすくなります。ただし、これらのファイルがモデルへ高度な対戦知識を与えるわけではありません。ツール結果を繰り返し無視する場合は、補助プロンプトを増やすより、ツール利用と長い指示の遵守に強いモデルを使う方が効果的です。

## データ鮮度と機能上の限界

- metaと実在構築データは環境とともに変化します。配布版が保証するのはページ上部に記載したローカルスナップショットであり、リアルタイム性は主張しません。
- dex、meta、teamサンプル、calculatorは同梱データを参照するため、通常利用にネットワークは不要です。新しいデータはスキル一式の更新で取得します。
- 過去seasonも検索できますが、旧レギュレーションを現行証拠へ自動混入させません。
- 図鑑データや計算式もルール変更の影響を受ける可能性があります。レギュレーションをまたぐ質問では対象season/ruleを明示してください。
- 全ターン状態、非公開情報、双方の選択を網羅することはできません。前提、信頼度、注意事項も結論の一部です。

## 今後の取り組み

- **手順の効率と互換性：**重複するツール呼び出しを減らし、各AIアシスタントがチーム構築の全工程を実行できるか検証します。
